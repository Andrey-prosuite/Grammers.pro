# Передача проекта в новый чат

Этот файл сохраняет контекст предыдущего чата. Начать с `AGENTS.md`, затем прочитать этот документ и `README.md`. Новые указания пользователя имеют приоритет.

## Проект и пожелания пользователя

- Сайт веб-студии **Grammers.pro**, репозиторий `https://github.com/Andrey-prosuite/Grammers.pro`, основная ветка `main`.
- Сначала делаем статическую вёрстку; позже переносим её в WordPress.
- Пользователю нравятся тексты и дизайн существующей главной: `https://grammers.pro/home-page`. Их нужно сохранить, но заменить громоздкую разметку Тильды чистым семантическим HTML и компактными стилями.
- Страницы собираются из независимых переиспользуемых блоков. Шаблон, стили и будущее поведение хранятся вместе. Базовый класс `.block-name`, вариант дополнительным классом `.block-name-individualclass` на том же элементе, внутренние элементы `.block-name__element`.
- Стили — SCSS с вложенностью. Будущее поведение — обычный JS и jQuery, без React/Vue.
- В будущем нужны GSAP, ScrollTrigger, анимации появления и плавный скролл. Lenis был предложен, но пользователь его не утверждал. GSAP и Lenis не установлены.
- **Текущий этап строго без клиентского JS, анимаций и эффектов. Не добавлять их при доработке главной. Тексты не переписывать, включая исходные опечатки.**
- Пользователь общается по-русски, работает в Windows 11 и GitHub Desktop, не знаком с localhost и терминальными командами. Давать конкретные короткие шаги и использовать подготовленные `.cmd`-файлы.
- Пользователю важно, чтобы согласованные изменения попадали в GitHub, а не оставались только в облачной рабочей папке. Коммиты и обычный push в `main` уже применялись по его просьбе; force push и потеря локальных правок недопустимы.
- Поддерживать `AGENTS.md` по мере изменения требований.

## Карта сайта

Предварительная структура пользователя:

1. Главная.
2. Портфолио и отдельный кейс.
3. Услуги и отдельная услуга — лендинг в общей дизайн-системе.
4. Информационный лендинг для разных SEO-запросов.
5. Блог и статья.
6. О нас.
7. Контакты.

Пока реализуется только главная. URL остальных страниц, набор услуг и способ редактирования блоков в WordPress (Gutenberg/ACF) ещё не утверждены. Не считать предложения предыдущего ассистента согласованными решениями.

## Что находится в репозитории

Стек: Vite 7, Nunjucks 3, Sass, jQuery 4 в зависимостях. Требуется Node.js >=22.12.0; пользователю рекомендуется Node.js 24 LTS с npm.

- `index.html` в корне — **исходный шаблон Nunjucks**, не готовый файл для открытия в браузере.
- `src/layouts/base.njk` — общий документ.
- `src/pages/home.njk` — порядок секций главной.
- `src/data/home.json` — тексты и данные, используются только сборщиком.
- `src/blocks/<name>/<name>.njk` и `<name>.scss` — независимые блоки.
- Блоки: site-header, hero, clients, approach, benefits, projects, metrics, featured-project, awards, credentials, platforms, services, contact, site-footer.
- `src/components/` — кнопка, заголовок секции, макрос сохранения переносов строк.
- `src/styles/main.scss` — подключение стилей через `@use`; tokens/base/layout — общие настройки.
- `public/images/` — все используемые изображения, локально.
- `dist/` — результат сборки с относительными путями, исключён из Git; не редактировать и не коммитить.

```sh
npm ci
npm run build
```

После сборки готовый файл — `dist/index.html`, CSS лежит в `dist/assets/`. В production нет `<script>`, inline-обработчиков, JS-bundle или внешних запросов ресурсов. `npm run dev` и `npm run preview` доступны для внутренних HTTP-проверок. Не выдавать loopback-адреса за доступный пользователю публичный предпросмотр.

## Оригинал Тильды и незавершённая визуальная сверка

Из-за сетевой блокировки пользователь предоставил ZIP сохранённой страницы «Главная by Andrey». По нему главная сверстана заново, без исполнения и переноса скриптов Тильды. Сырые HTML/ZIP и скриншоты предыдущей среды не находятся в Git; не предполагать, что новый чат имеет к ним доступ. Извлечённые тексты и нужные изображения уже сохранены в репозитории.

**Вёрстку нельзя считать точно совпавшей с живым оригиналом:**

- В архиве не было NTSomic Regular/Medium/Bold. Сейчас используется запасной Arial.
- Шесть изображений кейсов — только превью 20×16 px; фото менеджера — 20×20 px; длинный скриншот проекта также сохранён миниатюрой. Поэтому картинки размытые.
- Полные URL оригинальных картинок и размеры локальных файлов: `docs/reference-assets.json`.
- Три URL файлов шрифта: `docs/static-home.md`.
- Сохранённые логотипы, награды и иконки платформ доступны локально.

Если доступ появился: загрузить живую страницу и оригинальные ресурсы через разрешённые маршруты, заменить миниатюры по тем же локальным путям, добавить локальные `@font-face`, затем сравнить desktop/mobile с оригиналом. Проверить реальную композицию и отступы: текущая версия основана на сохранённой странице, а её анимационные состояния и отсутствие шрифта мешали точному сравнению. Не генерировать замену фотографиям и не выдавать увеличение миниатюр за восстановление оригиналов.

Статические особенности: форма не отправляется (disabled submit), «Макс» отключён — ссылки в оригинале не было. CTA ведут к форме; существующие кейсы и другие страницы — на действующий сайт. На мобильном навигация показана строкой ссылок без JS-бургера; логотипы и награды прокручиваются вручную. Все эти ограничения описаны в `docs/static-home.md`.

## Windows: как пользователь получает и открывает проект

Уже добавлены и отправлены в GitHub:

- `SYNC-FROM-GITHUB.cmd` → `tools/sync-from-github.ps1`: пока окно открыто, каждые 30 секунд получает fast-forward из `origin/main`. При локальных правках, untracked-файлах, другой ветке, локальных коммитах или конфликте истории обновление пропускается. Нет push/reset/stash, установки зависимостей или пересборки. Используется Git из PATH или установленного GitHub Desktop.
- `OPEN-SITE.cmd`: выполняет `npm ci`, `npm run build` и открывает `dist/index.html` без localhost. Если Node.js/npm отсутствуют, открывает официальную страницу загрузки. После установки Node.js нужно запустить файл снова.
- В `.gitattributes` закреплены CRLF для `.cmd`.

Пользователь уже показывал в браузере сырой `{% extends ... %}` из корневого `index.html`. Это открытие исходного шаблона без сборки, а не поломка HTML. Не повторять совет открывать корневой файл. Рекомендуемый путь: GitHub Desktop → Fetch origin → Pull origin (если появится) → Show in Explorer → двойной щелчок `OPEN-SITE.cmd`.

## Проблема сетевого доступа: причина перехода в новый чат

Последняя проверка в старой среде: запросы к `grammers.pro/home-page`, `static.tildacdn.com` и `djerin.ru` блокировались **прокси среды** с 403. Это не установило неисправность самих сайтов. GitHub Git read/push работали.

В черновик старого чата добавляли `grammers.pro`, но runtime продолжал показывать restricted policy с пустым списком дополнительных доменов. Попытка обновить черновик позднее вернула **CONFLICT / stale_base**: конфигурация уже изменилась или была опубликована после создания черновика. Сервер прямо сообщил, что повторное чтение и отправка того же старого черновика не исправят конфликт; нужен новый setup-чат от актуальной конфигурации.

Пользователь видел сообщение «Среда изменена. Загрузите актуальные настройки и проверьте свои изменения перед сохранением», а кнопка публикации была недоступна. Ассистент не мог сам применить/опубликовать конфигурацию. ZIP переноса пользователь скачать не смог, ссылки на `/workspace` из другого чата не работают. **Не отправлять его снова за тем же архивом или по кругу искать неподтверждённую кнопку.** Контекст теперь находится в GitHub.

В новом чате сначала проверить актуальную attached environment, runtime policy и реальный запрос. Если требуется изменение сетевой конфигурации, работать с новым актуальным черновиком и сохранять все существующие настройки. Для основной задачи нужны:

- `grammers.pro` — оригинальная страница;
- `static.tildacdn.com` — известные оригинальные картинки и шрифты;
- `djerin.ru` пользователь также просил проверить; к вёрстке Grammers этот сайт не относится.

Другие CDN добавлять только после обнаружения фактических необходимых адресов. Не отключать TLS, не обходить прокси и не считать сохранение черновика применением runtime policy. GitHub-аутентификация уже работала через платформу; отсутствие GH_TOKEN не означает, что нужно просить новый токен.

Отклонённое обновление старого черновика также предлагало правильный путь checkout `Grammers.pro`, SHA версии статической главной и инструкции запуска без JS. Оно **не было сохранено**. Не копировать старые SHA и весь список репозиториев вслепую: сначала проверить текущие checkout и HEAD новой среды, сохранить прочие репозитории и изменения.

## Состояние Git и начало следующей работы

На момент подготовки этого документа в GitHub `main` был коммит `28984cd` (OPEN-SITE); ранее `9c5b382` (автополучение файлов) и `9009f75` (статическая главная). Сам документ будет следующим коммитом. Всегда ориентироваться на актуальный удалённый `main`, не откатываться к перечисленным SHA.

1. Найти существующий checkout, проверить `git status` и актуальный `origin/main`; сохранить чужие изменения. Старое расположение было `/workspace/Grammers.pro`, но в новой среде оно может отличаться. Не создавать worktree без запроса пользователя.

3. В первую очередь проверить, появился ли доступ к оригинальному сайту и CDN в новой среде.
4. После восстановления доступа продолжить получение ресурсов и визуальную сверку статической главной, сохранив чистую структуру и тексты.
5. Если доступ всё ещё заблокирован, назвать конкретный текущий blocker и использовать поддерживаемый процесс актуальной конфигурации, без повторения прежнего цикла советов.
