# Архитектура и перенос в WordPress

Разработка и проверки выполняются локально в папке проекта. Коммиты и отправка изменений в GitHub выполняются только по явной команде пользователя.

Главная — `index.html`, кейсы — `cases.html`: обычные HTML с контентом, без шаблонизатора. Открывается как файл, ресурсы вёрстки локальные; SmoothScroll 1.4.10 загружается с согласованного CDN. Изображения — `images/`, готовый CSS — `styles.css`.

SCSS всех секций хранится в одном `src/styles/blocks.scss`, каждый блок отделён комментарием с названием и строками звёздочек. Отдельные папки и файлы стилей блоков больше не создаются; новые блоки добавляются секциями в тот же файл. Остальные общие стили — в `src/styles/`, компоненты — в `src/components/`. `main.scss` подключает модули через `@use`. Команда `npm run styles` обновляет отслеживаемый в Git `styles.css`. Vite используется по желанию для разработки и сборки. Сборка также обновляет CSS. Подключён обычный локальный JS `Modifications/modifications.js` для курсора карточек кейсов.

Классы и семантический DOM сохранять: `.block-name`, вариант `.block-name-individualclass`, элементы `.block-name__element`. Секции независимы от порядка соседей. Повторяемым экземплярам нужны уникальные ID и корректные ARIA-связи.

При переносе в WordPress выделить header.php, footer.php и template-parts/blocks/, сохраняя классы и DOM. Контент заменить полями WordPress; Gutenberg/ACF ещё не выбраны. Использовать esc_html, esc_attr, esc_url и wp_kses; ресурсы подключать через enqueue API. Предварительные PHP-заглушки не создавать.

Обычное превью project-card имеет пропорцию 16:9 на всех ширинах, высота вычисляется из ширины. Между рядами обеих сеток проектов — 80px. Дополнительный класс `project-card-featured` на article страницы cases.html задаёт grid-column: 1 / -1; для WordPress предусмотреть отдельное булево поле. Первый Brodeks отмечен как пример featured.

Актуальное исключение featured от 960px: высота изображения 85vh, aspect-ratio: auto. Размеры внутреннего экрана настраиваются CSS-переменными --project-screen-width/height/max-width на карточке: для featured это calc(100% - 50px), calc(100%), 900px; базовые значения на .project-card — 100%, 100%, 100%; такие же запасные значения сохранены в var() модификации. Радиус превью берётся из общего --radius-card: 25px; внутренний экран обычного кейса и featured до 959px со скруглением от 5px до 25px при появлении; featured от 960px — от 25px до 0px; радиусы заданы переменными --project-screen-radius-start/end. Поэтому эффект остаётся независимым от сетки. Общий фон обеих страниц и шапки белый: --color-background: #fff в tokens.scss; --LightGray: #F5F6F8 сохранён для --color-surface. Обводка контейнера картинки при hover от 960px, фокусе и мобильной эмуляции — псевдоэлемент ::after: inset 0, z-index 3, border 1px #e3e5e8, border-radius inherit, pointer-events none. Он рисуется поверх вложенного скриншота, не меняет DOM и геометрию. Reduced motion отключает плавное появление обводки.

Будущее поведение — обычный JS и jQuery, без фреймворков; GSAP и плавный скролл относятся к последующим этапам. Инициализация ограничена экземпляром блока, повторно безопасна; контент доступен без JS. В WordPress использовать штатный jQuery без второй копии.

Актуальная начальная трансформация экрана: perspective(1200px) translateY(0%) rotateX(7deg) scale(0.85); вертикального смещения нет, экран появляется из масштаба 0.85. Уход и прокрутка сохранены; появление экрана — opacity и transform по 0.75s cubic-bezier(0.16, 0.44, 0, 0.97) без задержки.

## Модификации

Правила: [Modifications/README.md](../Modifications/README.md). База — один общий `modifications.css` и один общий `modifications.js` в папке `Modifications/`. Каждый эффект выделяется секцией со строками звёздочек и взаимными ссылками в русских комментариях. Параметры референса фиксируются в README. Проверка — на главной, без отдельных демостраниц. Курсор `.go` со стрелкой подключён к карточкам кейсов. Vite сохраняет обычный скрипт локально через плагин конфигурации, чтобы исходный HTML оставался пригоден для прямого открытия.

Общий head всех страниц: CSS модификаций, CDN SmoothScroll 1.4.10 с SRI и crossorigin, затем обычный modifications.js. Оба скрипта defer, порядок сохранять. Настройки плавного скролла — секция 02 общего JS.

Карточка project-card переиспользуется в секциях обеих страниц с одной структурой DOM и общими стилями в blocks.scss. Область превью — div с фоном и доступным описанием, готовый для вложенных контейнеров. У карточки одна ссылка, охватывающая превью и заголовок; у неопубликованного кейса ссылки нет. Vite собирает обе HTML-точки входа и подключает общий скрипт модификаций в каждой.

Внутри `.project-card__media.go.project-preview` находятся слои `project-preview__backdrop`, `project-preview__veil` и `project-preview__stage > project-preview__screen > img.project-preview__screenshot`. Обёртки выше превью не менялись. Фоновый слой отдельно не увеличивается; screen обрезает длинный скриншот и задаёт контейнер для единиц cqh. У обычного кейса screen занимает 100% ширины и высоты превью, у featured на десктопе ширина ограничена 900px, высота равна высоте превью. CSS-секция 05 модификаций сохраняет параметры движения Djerin; секция 04 сжимает область превью до 95% при наведении от 960px; до 959px сжатие отключено и работает совместно с секцией 05. Сжатие превью использует transition: all 0.75s cubic-bezier(0.16, 0.44, 0, 0.97). Появление экрана (opacity и transform) использует те же 0.75s и кривую без задержки; уход экрана и длительность прокрутки сохранены; актуальная задержка прокрутки 200мс. Desktop-hover работает на CSS; до 959px JS секции 05 выбирает максимум одну картинку с |центр картинки − центр visualViewport| ≤ высота картинки до сжатия. Выбирается ближайшая к центру, при равенстве сохраняется текущая; заголовок не участвует. Через data-project-preview-active запускается тот же эффект. scroll/resize объединяются через requestAnimationFrame; ResizeObserver отслеживает размеры превью. Неизменная выбранная картинка не перезапускает анимацию. При desktop или скрытии вкладки активность снимается и запланированный кадр отменяется; destroy также отключает обработчики и ResizeObserver. ProjectPreview.init() повторно безопасен. При reduced motion CSS отключает движение; без JS фото и ссылки доступны. На всех 16 карточках обеих страниц временно один локальный скриншот brodeks-screen.webp (900×2400); позже заменить на индивидуальные; при переносе в WordPress предусмотреть отдельное поле скриншота каждого проекта.

На ширине до 959px featured-превью имеет height: auto и aspect-ratio: 16 / 9, как обычные кейсы; ширина и max-width внутреннего экрана — 100%, без бокового зазора. Высота 85vh, боковой зазор и max-width 900px действуют от 960px.

Зацикленная прокрутка начинается через 200мс после наведения, фокуса или мобильного выбора, пока экран ещё появляется (750мс). Первый проход project-preview-scroll-start сохраняет прежнюю кривую cubic-bezier(0.25, 0.1, 0.55, 1), длительность 12с и задержку 200мс. На 12.2с его без скачка продолжает project-preview-scroll: 12с на проход, cubic-bezier(0.45, 0, 0.55, 1), infinite alternate-reverse, начиная с обратного прохода. У цикла fill-mode: forwards, поэтому он не перекрывает первый старт до окончания своей задержки. Появление маски не повторяется; reduced motion отключает анимацию. При выключении эффекта анимация снимается и позиция скриншота сразу сбрасывается в 0. Каждый новый запуск начинается с начала с задержкой 200мс; позиция не сохраняется.

GO-курсор отображается кругом #242424 с белой стрелкой и mix-blend-mode: normal. Инверсия exclusion и исходные цвета сохранены в комментариях секции 01 Modifications/modifications.css.
