# Архитектура и перенос в WordPress

## Библиотеки блоков и модификаций

[Blocks/README.md](../Blocks/README.md) — первичная библиотека структуры и управления: шаблоны HTML, один blocks.scss/blocks.css, один blocks.js, интерфейсные изображения и инструкции агентам. Первые блоки — single-image и horizontal-gallery. [Визуальный каталог](../Blocks/index.html) открывается обычным файлом. Модификации — независимые эффекты из Modifications, применимые к библиотечным и другим блокам; код эффектов не копируется.

Библиотечные стили вынесены из src/styles/blocks.scss, остальные блоки пока остаются там. npm run styles собирает styles.css и Blocks/blocks.css. Страницы подключают оба CSS, Modifications/modifications.css и оба обычных JS: сначала Modifications/modifications.js, затем Blocks/blocks.js. Vite собирает три страницы сайта и служебный noindex-каталог. Галерея управляется только Blocks/blocks.js; ScrollReel и просмотрщик остаются модификациями. Контент не дублируется: общая images/, элементы интерфейса — Blocks/images/. Документация обеих библиотек обновляется автоматически в рамках изменений.


Интерфейсы всех модификаций описаны в [Modifications/AGENTS.md](../Modifications/AGENTS.md): разметка, настройки, значения по умолчанию, зависимости и жизненный цикл. По постоянному указанию пользователя инструкции для агентов обновляются автоматически при изменении модификаций и переиспользуемых блоков в рамках той же задачи; корневой AGENTS.md фиксирует это правило, профильные docs сохраняют детали блоков, Modifications/README.md — настройки эффектов.

Разработка и проверки выполняются локально в папке проекта. Коммиты и отправка изменений в GitHub выполняются только по явной команде пользователя.

Главная — `index.html`, список кейсов — `cases.html`, отдельный кейс — `case.html`: обычные HTML с контентом, без шаблонизатора. Открывается как файл, ресурсы вёрстки локальные; SmoothScroll 1.4.10 загружается с согласованного CDN. Изображения — `images/`, готовый CSS — `styles.css`.

Библиотечные блоки используют один Blocks/blocks.scss и один Blocks/blocks.js, общие эффекты — Modifications/modifications.css/js. Остальные секции пока хранятся в src/styles/blocks.scss с русскими разделителями. Новые библиотечные блоки добавляются секциями в общий файл библиотеки, без отдельных CSS/JS на каждый блок. Общие стили — src/styles/, компоненты — src/components/; main.scss подключает модули через @use. npm run styles обновляет отслеживаемые styles.css и Blocks/blocks.css. Vite необязателен для просмотра: обычный HTML со всеми локальными подключениями открывается файлом.

Классы и семантический DOM сохранять: `.block-name`, вариант `.block-name-individualclass`, элементы `.block-name__element`. Секции независимы от порядка соседей. Повторяемым экземплярам нужны уникальные ID и корректные ARIA-связи.

При переносе в WordPress выделить header.php, footer.php и template-parts/blocks/, сохраняя классы и DOM. Контент заменить полями WordPress; Gutenberg/ACF ещё не выбраны. Использовать esc_html, esc_attr, esc_url и wp_kses; ресурсы подключать через enqueue API. Предварительные PHP-заглушки не создавать.

Обычное превью project-card имеет пропорцию 16:9 на всех ширинах, высота вычисляется из ширины. Между рядами обеих сеток проектов — 80px. Дополнительный класс `project-card-featured` на article страницы cases.html задаёт grid-column: 1 / -1; для WordPress предусмотреть отдельное булево поле. Первый Brodeks отмечен как пример featured.

Актуальное исключение featured от 960px: высота изображения 85vh, aspect-ratio: auto. Размеры внутреннего экрана настраиваются CSS-переменными --project-screen-width/height/max-width на карточке: для featured это calc(100% - 50px), calc(100%), 900px; базовые значения на .project-card — 100%, 100%, 100%; такие же запасные значения сохранены в var() модификации. Радиус превью берётся из общего --radius-card: 25px; внутренний экран обычного кейса и featured до 959px со скруглением от 5px до 25px при появлении; featured от 960px — от 25px до 0px; радиусы заданы переменными --project-screen-radius-start/end. Поэтому эффект остаётся независимым от сетки. Общий фон обеих страниц и шапки белый: --color-background: #fff в tokens.scss; --LightGray: #F5F6F8 сохранён для --color-surface. Обводка контейнера картинки при hover от 960px, фокусе и мобильной эмуляции — псевдоэлемент ::after: inset 0, z-index 3, border 1px #e3e5e8, border-radius inherit, pointer-events none. Он рисуется поверх вложенного скриншота, не меняет DOM и геометрию. Reduced motion отключает плавное появление обводки.

Будущее поведение — обычный JS и jQuery, без фреймворков; SmoothScroll уже согласован, GSAP/ScrollTrigger подключены локально для новых анимированных блоков. Инициализация ограничена экземпляром блока, повторно безопасна; контент доступен без JS. В WordPress использовать штатный jQuery без второй копии.

Актуальная начальная трансформация экрана: perspective(1200px) translateY(0%) rotateX(7deg) scale(0.85); вертикального смещения нет, экран появляется из масштаба 0.85. Уход и прокрутка сохранены; появление экрана — opacity и transform по 0.75s cubic-bezier(0.16, 0.44, 0, 0.97) без задержки.

## Модификации

Правила: [Modifications/README.md](../Modifications/README.md). База — один общий `modifications.css` и один общий `modifications.js` в папке `Modifications/`. Каждый эффект выделяется секцией со строками звёздочек и взаимными ссылками в русских комментариях. Параметры эффекта фиксируются в README. Проверка — на главной, без отдельных демостраниц. Курсор `.go` со стрелкой подключён к карточкам кейсов. Vite сохраняет обычный скрипт локально через плагин конфигурации, чтобы исходный HTML оставался пригоден для прямого открытия.

Общий head всех страниц: CSS модификаций, CDN SmoothScroll 1.4.10 с SRI и crossorigin, затем обычный modifications.js. Оба скрипта defer, порядок сохранять. Настройки плавного скролла — секция 02 общего JS.

Карточка project-card переиспользуется в секциях обеих страниц с одной структурой DOM и общими стилями в blocks.scss. Область превью — div с фоном и доступным описанием, готовый для вложенных контейнеров. У карточки одна ссылка, охватывающая превью и заголовок; у неопубликованного кейса ссылки нет. Vite собирает три страницы сайта и служебный каталог Blocks/index.html, подключая общий скрипт модификаций и общий скрипт блоков в каждой.

Внутри `.project-card__media.go.project-preview` находятся слои `project-preview__backdrop`, `project-preview__veil` и `project-preview__stage > project-preview__screen > img.project-preview__screenshot`. Обёртки выше превью не менялись. Фоновый слой отдельно не увеличивается; screen обрезает длинный скриншот и задаёт контейнер для единиц cqh. У обычного кейса screen занимает 100% ширины и высоты превью, у featured на десктопе ширина ограничена 900px, высота равна высоте превью. CSS-секция 05 модификаций сохраняет параметры движения ; секция 04 сжимает область превью до 95% при наведении от 960px; до 959px сжатие отключено и работает совместно с секцией 05. Сжатие превью использует transition: all 0.75s cubic-bezier(0.16, 0.44, 0, 0.97). Появление экрана (opacity и transform) использует те же 0.75s и кривую без задержки; уход экрана и длительность прокрутки сохранены; актуальная задержка прокрутки 200мс. Desktop-hover работает на CSS; до 959px JS секции 05 выбирает максимум одну картинку с |центр картинки − центр visualViewport| ≤ высота картинки до сжатия. Выбирается ближайшая к центру, при равенстве сохраняется текущая; заголовок не участвует. Через data-project-preview-active запускается тот же эффект. scroll/resize объединяются через requestAnimationFrame; ResizeObserver отслеживает размеры превью. Неизменная выбранная картинка не перезапускает анимацию. При desktop или скрытии вкладки активность снимается и запланированный кадр отменяется; destroy также отключает обработчики и ResizeObserver. ProjectPreview.init() повторно безопасен. При reduced motion CSS отключает движение; без JS фото и ссылки доступны. На всех 16 карточках обеих страниц временно один локальный скриншот brodeks-screen.webp (900×2400); позже заменить на индивидуальные; при переносе в WordPress предусмотреть отдельное поле скриншота каждого проекта.

На ширине до 959px featured-превью имеет height: auto и aspect-ratio: 16 / 9, как обычные кейсы; ширина и max-width внутреннего экрана — 100%, без бокового зазора. Высота 85vh, боковой зазор и max-width 900px действуют от 960px.

Зацикленная прокрутка начинается через 200мс после наведения, фокуса или мобильного выбора, пока экран ещё появляется (750мс). Первый проход project-preview-scroll-start сохраняет прежнюю кривую cubic-bezier(0.25, 0.1, 0.55, 1), длительность 12с и задержку 200мс. На 12.2с его без скачка продолжает project-preview-scroll: 12с на проход, cubic-bezier(0.45, 0, 0.55, 1), infinite alternate-reverse, начиная с обратного прохода. У цикла fill-mode: forwards, поэтому он не перекрывает первый старт до окончания своей задержки. Появление маски не повторяется; reduced motion отключает анимацию. При выключении эффекта анимация снимается и позиция скриншота сразу сбрасывается в 0. Каждый новый запуск начинается с начала с задержкой 200мс; позиция не сохраняется.

GO-курсор отображается кругом #242424 с белой стрелкой и mix-blend-mode: normal. Инверсия exclusion и исходные цвета сохранены в комментариях секции 01 Modifications/modifications.css.

## Отдельный кейс Brodeks

case.html воспроизводит https://grammers.pro/brodeks, использует общие шапку, подвал, CSS и набор скриптов с defer. Vite собирает третью HTML-точку входа caseDetail. Страница открывается как локальный файл; хлебные крошки ведут на index.html и cases.html, услуги и CTA — в секции главной. Canonical — исходный /brodeks; ссылки карточек других страниц пока не менялись.

В main расположен article.case-study с одним H1. Вступление case-intro содержит название, ссылку на сайт, год и описание; single-image-cover — обложку; case-content — H2, абзацы и списки в двух колонках (до 959px в одной). case-stats — показатели через dl; case-brand — текст, фото и сведения о проекте; case-process — ход работ; case-details — композицию отдельных изображений интерфейса. single-image — img внутри одного кадра figure с layout content/inset/full/surface. horizontal-gallery — горизонтальные ленты прототипов и мобильных экранов, дипломы и детали; case-awards — дипломы и описание; case-cta — приглашение к проекту. Отступы заданы явно через case-section и модификаторы, без зависимостей от порядка соседей. Общий шрифт NTSomic и все стили блоков остаются в blocks.scss.

Галереи используют CSS scroll-snap и нативную прокрутку: стрелки ведут к первому/последнему изображению, миниатюры — к конкретному диплому. JS-слайдер, появление по скроллу и служебные обёртки Тильды не переносились. Мобильное меню case-варианта шапки — нативный details с одной навигацией для всех ширин.

По уточнению пользователя видео case-video запускается автоматически без звука и повторяется. Локальный MP4, poster и controls доступны без библиотек. Секция 06 общего JS ограничена video[data-case-video]: отключает autoplay при reduced motion, приостанавливает скрытую вкладку, сохраняет ручную паузу, поддерживает init/destroy. Ни один другой блок страницы не требует нового JS.

Ресурсы находятся в images/case/brodeks, оригиналы не увеличены; PNG/JPEG преобразованы в WebP quality 94. Текст страницы остаётся HTML; на картинках только оригинальные макеты интерфейса. Скрытые обрезанные элементы другого кейса из rec793229375 не копировались. Источники, размеры и ограничения — brodeks.md и brodeks-assets.json.

Для WordPress блоки переносятся в template-parts/blocks с полями заголовков, текста, списков, медиа, alt, параметров видео и списков слайдов. В фактах и показателях используются пары ключ/значение. Выбор Gutenberg/ACF не утверждён; PHP-заглушек и дублирующих шаблонов нет.

## Дополнительные сетки и просмотр изображений

По новому запросу согласованы блоки; они добавлены в case.html независимо от исходных секций Brodeks. case-layout ограничивает ширину, case-shot задаёт кадр, case-tabs — переключатель. case-pair содержит длинный десктоп и CSS-sticky телефон, case-pages — закреплённое описание/список и макеты, case-columns — две равноценные колонки. API init/destroy/open/close не зависит от case-блоков. Без JS ссылка открывает файл. Vite переписывает href в путь ресурса сборки; исходные HTML продолжают открываться напрямую. Общий CSS/JS имеет версию запроса, учитываемую плагином Vite.

При переносе в WordPress сетки становятся повторяемыми template-parts с полями медиа, подписей вкладок и контента; просмотрщик включается классом photo-zoom в шаблоне ссылки и подключается один раз через enqueue. PNG пользователя сохранён, WebP layout-demo.webp — полный 1920×11889 без обрезки; временно используется для всех новых экранов.

case-preview, case-split и case-next независимы; стили в blocks.scss, поведение в секциях 09/10 общих модификаций. Универсальный photo-parallax включается на контейнере с прямым img/picture/video, необязательный data-parallax-trigger включает внешнюю подпись. Старые data-case-parallax/data-parallax-media поддерживаются. Медиа курсора берётся из скрытого img[data-next-image] либо video[data-next-video] в блоке; ссылки и подписи остаются редактируемым контентом. В WordPress enqueue GSAP/ScrollTrigger только для нужных блоков, затем общий JS. Локальные UMD в Modifications/vendor соответствуют gsap 3.15.0 в package-lock.json; при обновлении зависимости обновить копии. Прямое открытие HTML без сборки сохранено. PhotoParallax/CaseNext имеют init/destroy, GSAP context/matchMedia, независимую очистку, reduced motion; строка приостановлена вне экрана, в скрытой вкладке и при просмотре изображения. Полные параметры и подключение: case-motion-blocks.md.

## Независимые модификации фотографий

photo-parallax и photo-zoom включаются отдельно или вместе на выбранных изображениях, без зависимости от case-блоков. PhotoParallax.destroy()/init() возвращает исходные стили и атрибуты; старый CaseParallax совместим. Просмотрщик делегирует клики a.photo-zoom/button.photo-zoom; прежний data-image-viewer работает. В WordPress подключать зависимости через enqueue по наличию выбранных эффектов. Документация: photo-modifications.md.

Контент кейса имеет общий верхний предел `--case-content-width: 1500px` (tokens.scss). Более узкие размеры блоков сохранены. Актуальные уточнения: case-pair/case-pages используют увеличенные отступы колонок относительно краёв при общем пределе 1500px; телефон занимает отдельную колонку своей фактической ширины. До 1023px case-pages/case-columns автоматически листают скриншоты по циклу case-pair (12s первый проход, затем по 12s туда/обратно), с управлением видимостью/reduced motion/просмотрщиком и паузой удержанием. case-columns использует data-screen-group. У всех четырёх карточек case-split__grid есть figcaption.case-split__caption.

## Горизонтальная галерея

Единый horizontal-gallery (Blocks/blocks.js) объединяет статичную ленту, равномерный цикл, реакцию на скролл и статичный режим со стрелками. data-gallery-mode: static/linear/scroll/controls. Во всех режимах нативные touch/тачпад и drag мышью; во время ручного жеста цикл приостановлен, затем продолжается с новой позиции. Стрелки связываются с экземпляром CSS-селекторами и могут быть в другом блоке. До 959px видны 20px следующей карточки. Параметры движения прежние; HorizontalGallery.init/destroy, ImageReel/CaseGallery — только псевдонимы. Прежние секции 11/12 содержат указатель на библиотеку Blocks. Концепция — controls, мобильные экраны — linear 60s, дипломы — static, детали — scroll 30s. Подключение и все настройки: [horizontal-gallery.md](horizontal-gallery.md).

Горизонтальная галерея: видимая лента занимает всю ширину экрана, max-width:none; корень размещать вне узкой колонки/обрезающих предков. Заголовки/описания ограничиваются отдельно. data-gallery-zoom="true" включает увеличение, по умолчанию false; обычные img поддерживают клик и Tab/Enter/Space без дополнительных обёрток, ссылки photo-zoom внутри галереи подчиняются опции. В текущих галереях увеличение включено только у «Деталей проекта».

При запросе нового блока галереи уточнять недостающие опции одним коротким вопросом: материалы, режим, скорость/длительность, зазор, размеры и радиус карточек, увеличение по клику, стрелки/их расположение для controls. Уже согласованные параметры повторно не спрашивать. Сохранять эти настройки в data-* и инструкции автоматически.

Сервисные страницы case-columns используют ту же внешнюю ширину, что case-pair/case-pages: min(100% - 2 × --page-gutter, --case-content-width), максимум 1500px. До 1023px одинаковые поля 20px. Две равные колонки и их зазор 20px на desktop, одна колонка и цикл скриншотов на mobile сохранены.

## Одиночное изображение

Единый single-image заменяет одиночные case-media, case-cover и case-preview. data-image-layout: content (по колонке до 1500px, по умолчанию), inset (поля --image-gutter:40px), full (вся ширина), surface (серый фон с теми же внешними полями и картинка по центру до 1500px). data-image-zoom и data-image-parallax независимы, стандарт false; только true включает эффект. Один кадр data-image-frame внутри figure, без дополнительных JS-обёрток и пустых ссылок. Параметры ImageViewer/PhotoParallax прежние, код эффектов остаётся в секциях 08/09. Нет отдельного контроллера. Обложка после заголовка — inset 40px, обе опции true, появление при загрузке сохранено. Полные примеры, CSS-переменные, адаптивность и очистка: [single-image.md](single-image.md). При новом блоке уточнять только недостающие опции; обновлять инструкции автоматически.

Инерция горизонтальной галереи: mouse drag затухает на 5% за условный кадр 60 Гц с учётом реального времени, без резкого snap. Статичные режимы замедляются до нуля без отскока; движущиеся плавно достигают штатной скорости ленты. Touch сохраняет браузерную инерцию: pointercancel не равен отпусканию, учитываются touchend и конец прокрутки. Возврат после native/обычного удержания — 1s expo.out от нуля. Автоматические длительности, реакция на скролл и шаг стрелок сохранены. data-gallery-inertia — служебное состояние, не записывать в HTML. Подробности в docs/horizontal-gallery.md; проверка: `node --test tests/horizontal-gallery-input.test.cjs`.

Второй эффект появления single-image: data-image-appear="rise" — y 300px→0, opacity 0→1, 1s power1.out, один раз, когда верх figure достигает 85% высоты экрана. Работает независимо от data-image-parallax и заменяет стандартное появление; отсутствие атрибута (auto) сохраняет прежнее поведение. Использует существующий PhotoParallax секции 09, без нового контроллера/обёрток, reduced motion и очистка сохранены. Тестовый блок #case-usability-image: surface, zoom false, parallax false, appear rise. При запросе нового одиночного изображения уточнять и вариант появления, если он не указан.

## Компонент и экземпляр блока

Обязательная методика: [Blocks/METHODOLOGY.md](../Blocks/METHODOLOGY.md). Компонент — библиотечный исходник с общими именами/классами. Экземпляр — независимая копия для места на странице с уникальными именами/классами/ID/API; разметка в HTML страницы, стили в src/styles/pages/*.scss → styles.css, JS в src/scripts/pages/*.js. Дальнейшие индивидуальные правки — в экземпляре; компонент и другие экземпляры не обновлять автоматически. Новое правило заменяет прежнее общее подключение компонентов к любому новому размещению. Первые изображения/галереи пока в явно описанном переходном состоянии; Cookie уже имеет три независимых экземпляра. Общие модификации при этом остаются подключаемыми эффектами, не копируются в каждый экземпляр.

Cookie: компонент03 в Blocks и экземпляры home/cases/brodeks с отдельными маркерами/контроллерами; кнопка в стиле шапки, появление900ms/скрытие600ms, подтверждение365дней. Подключение: [cookie-notice.md](../docs/cookie-notice.md).

Глобальная шторка: одно синхронное подключение `Modifications/page-transition.js` в head до CSS на всех страницах. Внутри CSS, ранняя маска и контроллер; GSAP общий или автоматически локальный vendor. Атрибуты body, список страниц и хранилище не нужны. Открытие действует также при прямом входе/обновлении. В WordPress подключать один раз через общую шапку темы. API PageTransition.init/destroy/preview; прежние тайминги, reduced motion, аварийное снятие и стабильная ширина сохранены. ## Локальная разработка с автокомпиляцией

Двойной щелчок по `START-DEV.cmd` запускает Vite на http://127.0.0.1:4181/ (или `npm run dev`). Оставить окно работающим; остановка — Ctrl+C. Каталог: http://127.0.0.1:4181/Blocks/index.html. Зависимости должны быть установлены через npm ci, Node >=22.12.0. Повторно запускать на занятом порту не нужно.

Сохранение SCSS в src/styles, src/components или Blocks автоматически компилирует **оба** отслеживаемых CSS — styles.css и Blocks/blocks.css — и обновляет браузер. Ошибка Sass сохраняет предыдущий рабочий CSS и показывается в браузере/терминале; после исправления работа продолжается. HTML и обычные JS модификаций/блоков/экземпляров тоже обновляют страницу. В dev убирается локальный query v, чтобы кеш Vite не удерживал устаревшие файлы; исходный HTML и production сохраняют версии. Плагин tools/vite-live-styles.mjs, общий компилятор tools/styles.mjs.

Просмотр идёт из корня исходников, **без /dist/**. Старые /dist/index.html, /dist/cases.html, /dist/case.html, /dist/Blocks/index.html перенаправляются к живым исходным страницам. npm run build отдельно создаёт production dist; сервер preview предназначен для проверки готовой сборки. npm run styles обновляет оба CSS без сервера. Для обычного двойного щелчка по HTML Node по-прежнему не нужен. Сервер слушает только локальный 127.0.0.1, порт4181 строгий.
