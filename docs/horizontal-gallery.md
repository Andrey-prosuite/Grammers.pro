# Горизонтальная галерея

Один библиотечный блок `horizontal-gallery`: базовые и служебные стили в Blocks/blocks.scss → Blocks/blocks.css, собственный контроллер в Blocks/blocks.js (блок02). Автоматический цикл подключает модификацию ScrollReel секции10, увеличение — ImageViewer секции08. Прежние секции11/12 модификаций содержат только указатель на библиотеку, отдельного контроллера там нет. [Шаблоны](../Blocks/templates/horizontal-gallery.html), [инструкции агентам](../Blocks/AGENTS.md), [визуальный каталог](../Blocks/index.html#horizontal-gallery).

## Разметка и режим

```html
<section class="horizontal-gallery" data-horizontal-gallery data-gallery-mode="static" data-gallery-zoom="false"
         style="--gallery-gap: 24px;" aria-label="Галерея проекта">
  <div class="horizontal-gallery__viewport" id="project-gallery" data-gallery-viewport
       tabindex="0" aria-label="Изображения проекта: горизонтальная прокрутка">
    <ul class="horizontal-gallery__track" data-gallery-track>
      <li class="horizontal-gallery__item" data-gallery-item>
        <img src="./images/case/brodeks/mobile-home.webp" width="242" height="455"
             alt="Главная страница проекта" loading="lazy" decoding="async">
      </li>
    </ul>
  </div>
</section>
```

`ul/li` и `div/figure` равноправны. Нужны окно, один flex-трек и непосредственные карточки с метками. Размеры `width/height` изображения сохраняют пропорции и резервируют место. На широком экране без заданной ширины карточки изображения используют собственные размеры; общей высоты или обрезки нет. Увеличение в галерее задаётся только явной опцией data-gallery-zoom="true" на корне; по умолчанию выключено, даже если внутри оставлены ссылки photo-zoom. Для обычного img дополнительные обёртки не нужны: JS делает его доступной кнопкой с Tab/Enter/Space, возвращает исходные атрибуты при очистке. Для полного изображения можно использовать ссылку photo-zoom с href, иначе открывается currentSrc/src. Вне галереи модификация photo-zoom независима и работает как раньше. При перетаскивании или удержании завершающий click не открывает просмотрщик.

| data-gallery-mode | Поведение |
| --- | --- |
| static | Ручная прокрутка, без автоматического движения и стрелок; режим по умолчанию, в том числе для неизвестного значения |
| linear | Бесконечное равномерное движение справа налево, без реакции на вертикальный скролл |
| scroll | Бесконечное движение с прежней реакцией на направление и скорость скролла: вниз — влево, вверх — вправо |
| controls | Статичная лента и кнопки, переходящие на соседнюю карточку |

Во всех режимах доступны перетаскивание левой кнопкой мыши, нативные touch/тачпад и клавиатура. Вертикальный скролл не превращается в горизонтальный. Порог drag мыши — 6 px; после отпускания действует инерция по скорости последних движений. Короткий клик по фото сохраняется. Нативная полоса скрывается после JS, до JS ручная прокрутка остаётся доступной.

## Внешние и внутренние стрелки

```html
<nav class="horizontal-gallery__controls" data-gallery-controls hidden aria-label="Галерея проекта">
  <button class="project-gallery-prev" type="button" hidden aria-controls="project-gallery" aria-label="Предыдущий слайд">←</button>
  <button class="project-gallery-next" type="button" hidden aria-controls="project-gallery" aria-label="Следующий слайд">→</button>
</nav>
<!-- На корне нужного экземпляра: -->
<div class="horizontal-gallery" data-horizontal-gallery data-gallery-mode="controls"
     data-gallery-prev-selector=".project-gallery-prev"
     data-gallery-next-selector=".project-gallery-next">
  <!-- Окно project-gallery, трек и карточки по образцу выше. -->
</div>
```

Селекторы ищутся во всём документе, поэтому кнопки могут находиться в другом блоке. Для каждого экземпляра использовать собственные классы или составной CSS-селектор; не подключать одну кнопку к двум галереям. Несколько кнопок одного направления поддерживаются. Невалидный селектор игнорируется. Без селекторов контроллер ищет внутри корня `.horizontal-gallery__prev` / `.horizontal-gallery__next`. Использовать настоящие `button`, уникальный ID окна и `aria-controls`. JS раскрывает кнопки/их контейнер с `data-gallery-controls`, отключает нужное направление на краях. Без JS кнопки скрыты. Шаг считается по реальным координатам карточек, gap и полям; последний шаг ограничен концом трека. Быстрые клики считают следующую цель без очереди анимаций. При разной ширине карточек таблицы шагов не нужны.

## Публичные настройки

| Настройка на корне | Значение по умолчанию | Назначение |
| --- | --- | --- |
| data-gallery-zoom | false | Увеличение изображения по клику; только true включает просмотрщик |
| data-gallery-mode | static | static / linear / scroll / controls |
| data-gallery-duration | 300 | Переход стрелок и клавиатуры, миллисекунды; 0 — мгновенно |
| data-gallery-linear-duration | 60 | Секунды полного прохода последовательности в linear |
| data-gallery-scroll-duration | 15 | Секунды базового прохода в scroll |
| data-gallery-prev-selector | Локальный класс __prev | CSS-селектор внешних кнопок назад |
| data-gallery-next-selector | Локальный класс __next | CSS-селектор внешних кнопок вперёд |
| --gallery-gap | 0px | Промежуток карточек; 0px — вплотную |
| --gallery-padding | 0px | Горизонтальные внутренние поля трека |
| --gallery-card-width | auto | Ширина карточки на широком экране; варианты concept/phones/awards задают свои размеры |
| --gallery-radius | 0px | Радиус изображения |

Большая длительность означает более медленное движение. Длительности движения должны быть положительными конечными числами; невалидные заменяются стандартными, переход стрелок допускает 0. Параметры считываются на init, после смены данных выполнить destroy/init.

Кривые не изменены: у перехода за 300 ms `.5 - cos(PI*t)/2`; у бесконечного хода `ease:none`. В scroll дельта scrollY × -.3, минимум скорости ±1, смена timeScale за 1 s `expo.out`, после остановки скролла сохраняется последнее направление. В linear timeScale всегда -1, тикера реакции на скролл нет. Зацикливание учитывает замыкающий gap.

## Ручное управление движущейся лентой

Автодвижение использует нативный scrollLeft того же окна. Во время удержания/drag/свайпа/горизонтального колеса цикл приостановлен. После mouse drag скорость затухает на 5% за кадр 60 Гц с пересчётом по реальному времени (одинаковый результат на 60/120 Гц). Скорость измеряется по последним 100 ms; остановка мыши перед отпусканием дольше 80 ms не создаёт ложного броска. В static/controls движение замедляется до нуля и ограничено краями без отскока. В linear/scroll инерция плавно сходится к штатной скорости/направлению ленты, затем управление незаметно передаётся циклу. Порог передачи — разница 0.01px за условный кадр, максимальный шаг времени 64 ms. Эти значения — константы контроллера, отдельных data-опций нет.

Touch сохраняет нативную прокрутку и инерцию. pointercancel сам по себе не запускает ленту: отслеживается фактическое отпускание через touchend/touchcancel, затем ожидается scrollend или 150 ms тишины прокрутки. После нативного движения/обычного удержания автоматическая скорость возвращается от нуля за 1s expo.out. Во время программной инерции scrollend игнорируется. После JS ручной скролл свободный, без резкого scroll-snap к карточке; стрелки по-прежнему выравнивают по одной карточке за 300ms. Для бесконечного хода создаются только декоративные повторы; координата переносится на эквивалентный участок последовательности без видимого скачка. Повторы исключены из Tab и accessibility tree, дублирующих ID нет. Просмотрщик сопоставляет клон оригиналу через ScrollReel.getOriginal().

Клавиатурный фокус останавливает автодвижение и делает доступными оригинальные ссылки. На самом окне ArrowLeft/Right листают карточки, Home/End ведут к границам исходной последовательности. При уходе фокуса движение продолжается. За пределами экрана, в скрытой вкладке и при открытом просмотрщике цикл приостановлен. Уменьшенное движение отключает автопрокрутку, стрелки работают мгновенно. Без GSAP остаются ручное управление и стрелки; без JS — нативное окно.

## Адаптивность и жизненный цикл

До 959 px ширина каждой карточки равна ширине окна минус левое поле, gap и 20 px. Поэтому в начальной/выровненной позиции видны ровно 20 px следующей карточки; это относится ко всем четырём режимам и вложенным галереям. В движущейся ленте видимая доля меняется по ходу цикла. Пропорции изображения сохраняются. После последней карточки статичной галереи следующей нет.

Галерея занимает всю ширину страницы: max-width:none, лента обрезается только краями экрана. Заголовок и описание могут оставаться в ограниченной колонке. Сам корень галереи размещать отдельной строкой вне контейнеров max-width/overflow/clip; не вкладывать его в узкую колонку. Галерея наград также вынесена в отдельную полную строку, описание под ней остаётся ограниченным. Не ставить overflow:visible на нативное окно: он нужен для скролла; ограничение убрано у внешней геометрии.

`HorizontalGallery.init()` / `.destroy()` повторно безопасны. Очистка удаляет наблюдателей, слушатели, таймеры, анимации и клоны, освобождает захват указателя, восстанавливает атрибуты кнопок/корня и исходные стили. `ImageReel` и `CaseGallery` оставлены только как псевдонимы этого же API, отдельных реализаций больше нет. Старую разметку перевести на общие классы и data-метки. Для динамического изменения списка карточек выполнить destroy/init. Размеры и изображения отслеживаются ResizeObserver и load; пересчёт сохраняет фазу движущейся ленты и ближайшую карточку статичной.

В WordPress выводить только оригинальные карточки, данные режима/длительностей и уникальные связи, общий JS/CSS подключать один раз через enqueue. Не сохранять служебные data-gallery-ready/dragging/animating/inertia, data-reel-ready/manual и клоны в HTML.

## Подключённые экземпляры

- Доработка изначальной концепции: controls, увеличение false, внешние кнопки по классам, переход 300 ms.
- Мобильная версия: linear, увеличение false, полный проход 60 s, без стрелок.
- Дипломы: static, увеличение false, миниатюры и якоря сохранены.
- Детали проекта: scroll, увеличение true, прежние 30 s; независимая настройка linear 60 s сохранена.

Блок case-next использует прежний ScrollReel в режиме строки и собственный медиакурсор. Он занимает всю ширину экрана, без максимума 1500 px и боковых полей контейнера. Размеры букв, расстояние между повторами и параметры движения сохранены.

## Добавление новой галереи по запросу пользователя

При новом запросе собрать недостающие опции одним коротким вопросом: материалы/состав карточек, режим (static/linear/scroll/controls), длительность нужного режима, зазор, размеры карточек на desktop и радиус, увеличение по клику, расположение/селекторы стрелок для controls. Уже названные или ранее согласованные настройки повторно не спрашивать. Можно предложить текущие стандартные значения, но не включать увеличение автоматически. Полная ширина ленты и мобильный край 20px — действующие общие правила. Не превращать вопрос о настройках в дополнительное разрешение на реализацию.

## Проверка ввода

`node --test tests/horizontal-gallery-input.test.cjs` проверяет настоящий контроллер с управляемыми временем/событиями: передачу touch-жеста браузеру, ожидание завершения нативного скролла, затухание mouse drag, совпадение расстояния на 60/120 Гц, границы статичной ленты, reduced motion и очистку. Это регрессионные проверки логики ввода; физический touch дополнительно проверяется на устройстве.

При новой установке применять [методику компонентов и экземпляров](../Blocks/METHODOLOGY.md): сначала выбрать источник (существующий экземпляр или исходный компонент), затем создать независимый экземпляр с уникальными именами/классами и кодом страницы. Текущие ранние установки этого блока пока относятся к явно описанному переходному состоянию.

Галерея логотипов главной создана по новой методике: clients-home — независимый экземпляр исходного компонента с отдельными CSS/JS страницы и API HomeClientsGallery. Режим scroll45s, увеличение false, все15 логотипов. [Инструкция](home-clients-gallery.md).

Награды главной: awards-home — независимая копия clients-home, scroll45s,7 исходных SVG. [Инструкция](home-awards-gallery.md).
