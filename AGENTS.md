## Цель и стек

Разрабатываем статическую вёрстку сайта с последующим переносом в WordPress. Страницы состоят из повторно используемых блоков с разным контентом и небольшими вариациями оформления.

- Обычный корневой index.html без шаблонизатора. Vite — для необязательной разработки и сборки. Корневой HTML должен открываться двойным щелчком без Node.js.
- Исходные стили — SCSS с вложенностью; результат сборки — обычный CSS.
- Обычный JavaScript в ES-модулях и jQuery. Не вводить React, Vue или другой клиентский фреймворк без запроса пользователя.
- Node.js >= 22.12.0, зависимости устанавливать через `npm ci`; сохранять `package-lock.json` при изменении зависимостей.
- Для будущих анимаций сайта использовать GSAP: появления и сценарии по скроллу через ScrollTrigger. Для плавного скролла согласован SmoothScroll 1.4.10 через CDN; GSAP ещё не установлен.
- Общую инфраструктуру скролла держать отдельно от анимаций блоков; учитывать `prefers-reduced-motion`, очистку анимаций и работу якорей. Не скрывать контент навсегда при ошибке JS.

## Планируемые страницы

- Оригинал: `https://grammers.pro/home-page` (существующая страница на Тильде).

Миниатюрами пока остаются фото менеджера и длинный скриншот проекта. Не выдавать их за полноразмерные изображения и не заявлять точное визуальное совпадение до получения оригиналов; см. `docs/static-home.md` и `docs/reference-assets.json`.
- Основной этап — обычный HTML и SCSS. По новому указанию подключён локальный JS-эффект курсора на карточках кейсов; также согласован глобальный SmoothScroll 1.4.10, также согласована модификация smart-header и мобильный автозапуск превью кейсов. Прочее поведение пока не добавлять; GSAP относится к последующим этапам.
- Для всех страниц и переиспользуемых карточек применять компактный семантический DOM: один H1 страницы, последовательные уровни заголовков, article для самостоятельного кейса, одна обычная ссылка с заголовком внутри; без дублирующих/пустых ссылок. Превью — расширяемый div.project-card__media с CSS-фоном и доступным описанием role="img"/aria-label, по указанию пользователя. Не возвращать разметку и служебные контейнеры Тильды.
- Минимизировать DOM: семантические элементы, только необходимые обёртки, без служебной разметки и стилей Тильды. Сохранять доступность, адаптивность и SEO-смысл заголовков.

URL, состав секций, модель редактирования WordPress и окончательная навигация ещё обсуждаются. Не считать предложения в обсуждении утверждёнными требованиями.

## Структура и блоки

- Все стили блоков хранить в одном `src/styles/blocks.scss`, подключённом через `@use` из `src/styles/main.scss`. Не создавать отдельные папки и файлы стилей для каждого блока.
- Каждый блок в `blocks.scss` отделять секцией-комментарием: строка `/` со звёздочками, название блока на русском с его CSS-именем, закрывающая строка со звёздочками и `/`. Сохранять порядок секций и исходную SCSS-вложенность. Новые блоки добавлять в этот же файл отдельной секцией.
- `src/components/`: стили небольших переиспользуемых элементов.
- `index.html` и `cases.html`: обычные HTML-страницы, каждая содержит свою разметку и контент. `images/`: ресурсы. `styles.css`: готовый CSS в Git, обновлять через `npm run styles` после изменений SCSS. Не возвращать шаблонизатор без запроса пользователя.
- `src/styles/`: общие токены, базовые стили и контейнеры. Стили всех секций находятся в общем `src/styles/blocks.scss`.
- Базовый класс `.block-name` содержит общие правила. Дополнительный `.block-name-individualclass` задаёт отличия на том же элементе: `class="hero hero-home"`.
- Внутренние элементы именовать `.block-name__element`; использовать SCSS-вложенность `&__element`, `&:hover`, `&.block-name-variant`, избегать глубокой вложенности.
- `project-card` — общая карточка на главной и cases.html. Статическая структура: article.project-card → a.project-card__link (если есть реальная ссылка) → div.project-card__media + заголовок. Для неопубликованного кейса не придумывать ссылку. На cases.html заголовок H2, в секции главной — H3.
- На ширине до 959px featured-превью имеет height: auto и aspect-ratio: 16 / 9, как обычные кейсы; ширина и max-width внутреннего экрана — 100%, без бокового зазора. Высота 85vh, боковой зазор и max-width 900px действуют от 960px.
- Обычные превью кейсов имеют пропорцию Full HD 16:9 на всех ширинах. Вертикальный промежуток между рядами обеих сеток — 80px. На cases.html класс `project-card-featured` на article растягивает кейс на отдельную строку (`grid-column: 1 / -1`), высота его изображения — 85vh; первый Brodeks отмечен как пример. На десктопе внутренний экран featured имеет максимальную ширину 900px, ширину не больше calc(100% - 50px) и высоту calc(100%), то есть без зазора сверху и снизу. Радиус внешнего превью — 25px через --radius-card, внутренний экран обычного кейса и featured до 959px со скруглением от 5px до 25px при появлении; featured от 960px — от 25px до 0px. При переносе в WordPress предусмотреть переключатель featured.
- Фон главной и страницы кейсов — #F5F6F8 через CSS-переменную `--LightGray` в tokens.scss. Общие `--color-background` и `--color-surface` ссылаются на неё; шапка наследует общий цвет фона через существующий токен.
- Не связывать блок с порядком соседей, глобальными тегами или классом страницы. Общие зависимости должны быть явными.
- Повторяемые секции сохраняют одинаковую семантическую структуру. Для нескольких экземпляров блока обеспечивать уникальные ID и корректные ARIA-связи.
- JS ограничивать экземпляром блока, делать инициализацию повторно безопасной. Для поведения использовать `data-*`; jQuery импортировать через `import $ from 'jquery'`.
- Сохранять семантику HTML, управление с клавиатуры, видимый фокус и доступность контента без JS. Проверять адаптивность.

## Модификации

- Обязательные правила, алгоритм и каталог: [Modifications/README.md](Modifications/README.md). Читать при работе над эффектами.
- Модификация — самостоятельный эффект на CSS и/или JS. База хранится в `Modifications/modifications.css` и `Modifications/modifications.js`: один общий файл стилей и один общий файл кода.
- Каждый эффект выделять секцией со строками звёздочек, номером и названием. В комментариях давать отсылку к соответствующей секции другого файла, описывать запуск, разметку, настройки, зависимости и очистку. Все комментарии на русском.
- Параметры доступного референса считывать из CSS/JS, фиксировать источник в README; не заменять их приблизительными значениями.
- Отдельные демостраницы не создавать. Проверять модификации на целевых элементах страниц сайта.
- GO-курсор: инверсия отключена (mix-blend-mode: normal), круг #242424, стрелка #fff. Исходные exclusion и цвета сохранены в комментариях секции 01 CSS для восстановления.
- `go-cursor` воспроизводит параметры Cuberto локально на нативном JS; подключён к области `.project-card__media.go` карточек главной и cases.html. Также согласован SmoothScroll 1.4.10 с параметрами пользователя для всех страниц: CDN с SRI перед общим JS, оба с defer. Новые страницы должны подключать тот же общий набор.
- Hover превью: на всех 16 карточках главной и cases.html действует секция 05 — `project-preview`, эффект экрана сайта по Djerin. Менять только существующий контейнер `.project-card__media` и его содержимое; выше по DOM ничего не менять. Фоновая картинка отдельно не масштабируется; поверх затемнения появляется экран с 3D-стартом и скриншотом, циклически движущимся до конца и обратно по 12 с в каждую сторону после начальной задержки 200 мс, ещё во время появления экрана (750 мс). Логотип поверх фона не нужен. Анимация выполняется на CSS; до 959px согласован JS-выбор одной ближайшей к центру экрана картинки в пределах ± её высоты; подписи не учитываются. Точные параметры — `Modifications/README.md`.
- Текущий эксперимент: экран обычного кейса занимает 100% ширины и высоты превью без внутренних полей; в featured от 960px экран ограничен шириной 900px и занимает всю высоту без вертикального зазора; до 959px его ширина и max-width равны 100%, без боковых полей. Затемнение и появление из перспективы сохранены, радиус превью — 25px; экран обычного кейса и featured до 959px меняет скругление с 5px до 25px; featured от 960px — с 25px до 0px за время появления.
- Переменные размеров --project-screen-width/height/max-width явно заданы на .project-card (100%); featured переопределяет их. --project-preview-unit задан на .project-preview и адаптируется от 1024px. Радиусы экрана задают явно объявленные на .project-card переменные --project-screen-radius-start/end: 5px/25px; featured от 960px переопределяет их на 25px/0px. Появление — 750мс с кривой появления; возврат к стартовому радиусу за 850мс с кривой ухода. Фокус повторяет hover; reduced motion отключает переход.
- Скриншот циклически идёт до конца и плавно обратно: первый CSS-проход и затем project-preview-scroll с infinite alternate-reverse, 12с на проход и 200мс перед первым проходом. Первый проход project-preview-scroll-start сохраняет прежнюю кривую cubic-bezier(0.25, 0.1, 0.55, 1). На 12.2с включается project-preview-scroll с cubic-bezier(0.45, 0, 0.55, 1), infinite alternate-reverse forwards: первый старт не перекрывается, дальнейшее замедление симметрично. При выключении позиция сразу сбрасывается, новый запуск всегда с начала. До 959px сжатие контейнера отключено и margin-top заголовка 15px; reduced motion отключает animation.
- Стартовая трансформация экрана по последнему запросу: `perspective(1200px) translateY(0%) rotateX(7deg) scale(0.85)`. Кривые, длительности, задержки и затемнение сохранены. Это актуальное отличие от исходных значений Djerin.
- Секция 04 снова действует на всех карточках вместе с секцией 05: от 960px при наведении на article весь контейнер изображения сжимается до scale(0.95); до 959px контейнер не сжимается, переход all 0.75s cubic-bezier(0.16,0.44,0,0.97). Появление экрана по opacity и transform — те же 0.75s и кривая без задержки; уход и прокрутка сохранены. На всех 16 карточках обеих страниц временно подключён пользовательский скриншот Brodeks `images/projects/brodeks-screen.webp` (900×2400, верх исходника после уменьшения с 1920px до 900px, WebP quality 92). По запросу пользователя позже заменить на индивидуальные скриншоты соответствующих сайтов. Фото на фоне сохранены. До 959px активна максимум одна картинка: |центр картинки − центр видимой области экрана| ≤ высота картинки до сжатия. Из подходящих выбирается ближайшая, при равенстве сохраняется текущая. Подпись не участвует. Активность задаётся data-project-preview-active на превью; на мобильной ширине сжатие отключено, margin-top заголовка 15px. Положение пересчитывается через requestAnimationFrame по scroll/resize и изменению размеров превью; неизменный выбор не перезапускает анимацию. Очистка и повторный запуск — ProjectPreview.destroy()/init(); reduced motion отключает движение, ссылки доступны без JS.
- `smart-header` (секция 03) применён к `.uc-smart-header` главной: скрытие вниз от 150 px, показ вверх от 100 px, до 50 px всегда виден; переход transform 1 с.
- Сохранять изоляцию эффектов, несколько экземпляров, очистку, доступность и reduced motion. Базовые стили секций находятся в `src/styles/blocks.scss`.

## Подготовка к WordPress

- Сохранять независимые секции и стабильные CSS-классы для переноса в `template-parts/blocks/`.
- Не дублировать статические шаблоны предварительными PHP-заглушками. Выбор Gutenberg/ACF пока не сделан.
- При переносе использовать WordPress API для контента, меню, ресурсов и экранирования вывода.
- Подключать стили и скрипты через enqueue API. Использовать jQuery WordPress без второй копии, проверив совместимость API с её версией.
- Подробности архитектуры: `docs/architecture.md`.

## Проверка и Git

- `npm run dev` — сервер разработки; `npm run build` — сборка; `npm run preview` — проверка сборки. Итоговый `dist/index.html` с относительными путями также предназначен для открытия двойным щелчком, без localhost.
- На текущем этапе разрешён локальный `Modifications/modifications.js`; также разрешён CDN SmoothScroll 1.4.10 с SRI; проверять отсутствие inline-обработчиков и прочих внешних ресурсов в production HTML; форма не отправляется до отдельной реализации backend.
- После изменений HTML, стилей или JS выполнять сборку. При изменении поведения проверять его в браузере; при изменении вёрстки — мобильную и широкую ширину.
- Для изменений только документации сборка не требуется; проверить diff и `git diff --check`.
- Не редактировать `dist/` и `node_modules/`, не коммитить их или секреты.
- Сохранять чужие изменения; не применять force push и не переписывать историю без явного запроса.
- Разработку и проверки выполнять локально в папке проекта. Создавать коммиты и отправлять изменения в GitHub только по явной команде пользователя; согласование правок само по себе не разрешает коммит или push. Основная ветка — `main`; репозиторий — `Andrey-prosuite/Grammers.pro`. После запрошенной отправки сообщать результат.
- Облачный localhost недоступен на компьютере пользователя. Не выдавать внутренний адрес за публичный предпросмотр и не обещать доступ по неподтверждённой ссылке.
- Пользователь работает в Windows 11 и GitHub Desktop. Для автоматического получения исходников предусмотрен `SYNC-FROM-GITHUB.cmd` → `tools/sync-from-github.ps1`: только fast-forward из `origin/main`, без push/reset/stash, с пропуском локальных правок, неотслеживаемых файлов и локальных коммитов. Не добавлять автоматическую отправку или сброс изменений без отдельного запроса. Скрипт не устанавливает зависимости и не пересобирает `dist/`.
- Для просмотра на Windows открыть корневой index.html или OPEN-SITE.cmd двойным щелчком. Node.js и сборка не нужны.
