# Правила работы над Grammers.pro

Подтверждённый продуктовый контекст Impeccable — [PRODUCT.md](PRODUCT.md): аудитория производителей/брендов B2B/B2C, обращения как цель сайта, кейсы как отраслевые посадочные. Поддерживать его при изменении этих договорённостей; технические правила остаются здесь. В .impeccable/config.json пользователь выбрал buildPath=code (начинать новые страницы сразу с кода); это настройка процесса, а не свойство продукта. Конфигурация live подготовлена без внедрения скриптов; cspChecked=false до проверки доступным движком.

Новая редакция Brodeks находится отдельно в brodeks.html; case.html сохранена. Источник — последние текстовые экземпляры case.html, по указанию пользователя. Независимые классы text-summary-brodeks-story, text-tasks-brodeks-story-tasks/results, text-feature-brodeks-story-{место}; SCSS pages/brodeks-story.scss. Cookie — data-cookie-notice-brodeks-story и BrodeksStoryCookieNotice в pages/brodeks-story.js. Серые медиакадры статичны и декоративны, общий TextReveal14 подключён явно. Vite собирает четыре страницы сайта и каталог. [Подключения, настройки, адаптив, очистка и карта](docs/brodeks-story.md).

Для продолжения в новом чате прочитать `docs/HANDOFF.md`: там контекст пользователя, состояние реализации и нерешённая проблема доступа к оригиналу.

## Цель и стек

Разрабатываем статическую вёрстку сайта с последующим переносом в WordPress. Страницы состоят из повторно используемых блоков с разным контентом и небольшими вариациями оформления.

- Обычный корневой index.html без шаблонизатора. Vite — для необязательной разработки и сборки. Корневой HTML должен открываться двойным щелчком без Node.js.
- Исходные стили — SCSS с вложенностью; результат сборки — обычный CSS.
- Обычный JavaScript в ES-модулях и jQuery. Не вводить React, Vue или другой клиентский фреймворк без запроса пользователя.
- Node.js >= 22.12.0, зависимости устанавливать через `npm ci`; сохранять `package-lock.json` при изменении зависимостей.
- Для будущих анимаций сайта использовать GSAP: появления и сценарии по скроллу через ScrollTrigger. Для плавного скролла согласован SmoothScroll 1.4.10 через CDN; GSAP 3.15.0 и ScrollTrigger установлены и подключены локально на всех трёх страницах для согласованных модификаций.
- Общую инфраструктуру скролла держать отдельно от анимаций блоков; учитывать `prefers-reduced-motion`, очистку анимаций и работу якорей. Не скрывать контент навсегда при ошибке JS.

## Структура и блоки

- Компонент и экземпляр различаются по обязательной [методике Blocks/METHODOLOGY.md](Blocks/METHODOLOGY.md): перед использованием выяснить источник (существующий экземпляр или исходный компонент), если он не указан. Новые экземпляры получают уникальные классы/ID/API и свой CSS/JS страницы. Это правило важнее прежнего общего подключения компонентов.

- Библиотека блоков первична: `Blocks/` содержит шаблоны HTML, общий `blocks.scss` → `blocks.css`, общий `blocks.js`, `AGENTS.md`, каталог и интерфейсные изображения. Одиночное изображение и горизонтальная галерея уже перенесены; остальные блоки пока в `src/styles/blocks.scss`. Модификации из `Modifications/` подключаются к библиотечному или произвольному блоку. Не создавать отдельный CSS/JS для каждого исходного компонента; код экземпляров хранить в файлах страницы по методике. Читать [Blocks/AGENTS.md](Blocks/AGENTS.md) при работе с библиотечными блоками.
- Каждый блок в `blocks.scss` отделять секцией-комментарием: строка `/` со звёздочками, название блока на русском с его CSS-именем, закрывающая строка со звёздочками и `/`. Сохранять порядок секций и исходную SCSS-вложенность. Новые библиотечные блоки добавлять отдельной секцией в `Blocks/blocks.scss` и в каталог; прочие секции пока остаются в этом файле.
- `src/components/`: стили небольших переиспользуемых элементов.
- `index.html`, `cases.html` и `case.html`: обычные HTML-страницы, каждая содержит свою разметку и контент. `images/`: ресурсы. `styles.css`: готовый CSS в Git, обновлять через `npm run styles` после изменений SCSS. Не возвращать шаблонизатор без запроса пользователя.
- `src/styles/`: общие токены, базовые стили и контейнеры. Остальные стили секций находятся в общем `src/styles/blocks.scss`; библиотечные — в `Blocks/blocks.scss`.
- Базовый класс `.block-name` содержит общие правила. Дополнительный `.block-name-individualclass` задаёт отличия на том же элементе: `class="hero hero-home"`.
- Внутренние элементы именовать `.block-name__element`; использовать SCSS-вложенность `&__element`, `&:hover`, `&.block-name-variant`, избегать глубокой вложенности.
- Контент страницы кейса ограничен сверху значением --case-content-width: 1500px из tokens.scss; более узкие блоки сохраняют свои размеры. Ограничение применяется к обычным секциям. Горизонтальные галереи и case-next — исключения: лента до краёв экрана без max-width. case-next: вся ширина экрана без боковых полей и ограничения 1500px. У серых single-image[data-image-layout="surface"], case-video и case-details ширину поверхности не ограничивать: ограничивается внутреннее медиа; композиция case-details использует один общий case-details__composition, чтобы сохранять взаимное расположение картинок.
- `case.html` — отдельный кейс Brodeks по https://grammers.pro/brodeks: тексты и локальные оригинальные изображения, вступление, текстовые секции, показатели, видео, сведения о бренде, композиция интерфейсов, галереи, результаты и награды. Общие шапка/подвал, в шапке case-вариант с нативным details для мобильного меню. Блоки case-* независимы, стили в blocks.scss. Галереи объединены в horizontal-gallery: static/linear/scroll/controls через data-gallery-mode, нативный touch и drag мышью во всех режимах; стрелки листают по карточке и могут быть внешними через CSS-селекторы на корне. Контроллер библиотеки Blocks/blocks.js — HorizontalGallery.init/destroy; прежние секции 11/12 модификаций содержат только указатель на библиотеку; docs/horizontal-gallery.md. Миниатюры дипломов сохранены. По отдельному уточнению пользователя согласовано оригинальное видео с autoplay/muted/loop/playsinline; controls позволяют остановить его, секция 06 общего JS учитывает reduced motion и скрытие вкладки. Canonical сохраняет /brodeks. Ссылки существующих карточек пока не переключать автоматически. Vite собирает все три страницы. Источники и особенности: docs/brodeks.md, docs/brodeks-assets.json.
- Новые case-блоки со sticky и вкладками: case-layout (ограниченная сетка 1312/1512, максимум 1312px), case-pair (гибкая десктопная колонка и правая по фактической ширине телефона, телефон sticky по центру с сохранением 318:673 и высотой не больше 100svh - 50px), case-pages (закреплённые текст/список слева и выбранный длинный макет справа), case-columns (две равные обычные колонки). Примеры добавлены в конце case.html перед CTA; стили в blocks.scss. До 1023px пара переключается вкладками «Десктоп / Мобилка», оба кадра автоматически листаются по текущим параметрам карточек; у case-pages/case-columns до 1023px — тот же автоматический цикл, что у мобильного окна пары; на desktop их длинные изображения статичны. Без JS/reduced motion мобильные окна листаются вручную. case-columns использует data-screen-group без вкладок. Секция 07 общего CSS/JS отвечает за вкладки, видимость, паузу удержанием мыши и reduced motion. Размеры/закрепление выполняет CSS. Во всех новых примерах временно один пользовательский images/case/layout-demo.webp, 1920×11889, quality 92, без обрезки; исходный images/case/тест лендинга.png сохранён. Подробности и подключение: docs/case-blocks.md.
- case-pair/case-pages используют общий предел 1500px и увеличенный межколоночный промежуток, сопоставимый с внешними полями (max(--page-gutter, (100vw - --case-content-width) / 2), не более трети ширины сетки). Телефон не прижат к десктопу, правая колонка равна его фактической ширине; sticky по центру и предел высоты сохранены. До 1023px — прежние поля 20px, вертикальный промежуток 24px. У каждой карточки case-split__grid обязателен figcaption.case-split__caption.
- Общий просмотрщик — секция 08 CSS/JS: a.photo-zoom с href полного изображения (data-image-viewer сохранён для совместимости) и вложенным img, необязательный data-image-title. Подключён к новым кадрам и обложке; остальные изображения включать явно. Vite преобразует локальные href просмотрщика в пути ресурсов сборки. Без JS обычные ссылки и изображения доступны. Общий CSS/JS в исходных HTML имеет версию запроса для обновления кеша.

- Согласованные параметры модификаций фиксировать в инструкции без внешней атрибуции и ссылок на примеры. Не добавлять упоминания происхождения эффектов в код, комментарии, документацию или имена файлов. Лицензионные уведомления сторонних библиотек сохранять.

- GO-курсор: инверсия отключена (mix-blend-mode: normal), круг #242424, стрелка #fff. Исходные exclusion и цвета сохранены в комментариях секции 01 CSS для восстановления.

Менять только существующий контейнер `.project-card__media` и его содержимое; выше по DOM ничего не менять. Фоновая картинка отдельно не масштабируется; поверх затемнения появляется экран с 3D-стартом и скриншотом, циклически движущимся до конца и обратно по 12 с в каждую сторону после начальной задержки 200 мс, ещё во время появления экрана (750 мс). Логотип поверх фона не нужен. Анимация выполняется на CSS; до 959px согласован JS-выбор одной ближайшей к центру экрана картинки в пределах ± её высоты; подписи не учитываются. Точные параметры — `Modifications/README.md`.

Затемнение и появление из перспективы сохранены, радиус превью — 25px; экран обычного кейса и featured до 959px меняет скругление с 5px до 25px; featured от 960px — с 25px до 0px за время появления.

Появление — 750мс с кривой появления; возврат к стартовому радиусу за 850мс с кривой ухода. Фокус повторяет hover; reduced motion отключает переход.

Первый проход project-preview-scroll-start сохраняет прежнюю кривую cubic-bezier(0.25, 0.1, 0.55, 1). На 12.2с включается project-preview-scroll с cubic-bezier(0.45, 0, 0.55, 1), infinite alternate-reverse forwards: первый старт не перекрывается, дальнейшее замедление симметрично. ## Локальная разработка с автокомпиляцией

Двойной щелчок по `START-DEV.cmd` запускает Vite на http://127.0.0.1:4181/ (или `npm run dev`). Оставить окно работающим; остановка — Ctrl+C. Каталог: http://127.0.0.1:4181/Blocks/index.html. Зависимости должны быть установлены через npm ci, Node >=22.12.0. Повторно запускать на занятом порту не нужно.

Сохранение SCSS в src/styles, src/components или Blocks автоматически компилирует **оба** отслеживаемых CSS — styles.css и Blocks/blocks.css — и обновляет браузер. Ошибка Sass сохраняет предыдущий рабочий CSS и показывается в браузере/терминале; после исправления работа продолжается. HTML и обычные JS модификаций/блоков/экземпляров тоже обновляют страницу. В dev убирается локальный query v, чтобы кеш Vite не удерживал устаревшие файлы; исходный HTML и production сохраняют версии. Плагин tools/vite-live-styles.mjs, общий компилятор tools/styles.mjs.

Просмотр идёт из корня исходников, **без /dist/**. Старые /dist/index.html, /dist/cases.html, /dist/case.html, /dist/Blocks/index.html перенаправляются к живым исходным страницам. npm run build отдельно создаёт production dist; сервер preview предназначен для проверки готовой сборки. npm run styles обновляет оба CSS без сервера. Для обычного двойного щелчка по HTML Node по-прежнему не нужен. Сервер слушает только локальный 127.0.0.1, порт4181 строгий.
