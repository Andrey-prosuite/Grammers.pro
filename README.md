# Grammers.pro

[PRODUCT.md](PRODUCT.md) содержит подтверждённую аудиторию, назначение сайта, позиционирование и продуктовые ограничения. Для Impeccable выбран code-first в .impeccable/config.json. Подготовлена конфигурация live для корневых HTML и каталога; режим не запущен, проверка CSP движком не выполнена (cspChecked=false).

Новая страница кейса — [brodeks.html](brodeks.html). Открывается двойным щелчком; в запущенной разработке — http://127.0.0.1:4181/brodeks.html. Новые тексты собраны на последних текстовых блоках, вместо изображений стоят пустые серые кадры. Прежняя case.html сохранена. [Устройство и карта экземпляров](docs/brodeks-story.md).

## Библиотеки блоков и модификаций

[Blocks/README.md](Blocks/README.md) — первичная библиотека структуры и управления: шаблоны HTML, один blocks.scss/blocks.css, один blocks.js, интерфейсные изображения и инструкции агентам. Первые блоки — single-image и horizontal-gallery. [Визуальный каталог](Blocks/index.html) открывается обычным файлом. Модификации — независимые эффекты из Modifications, применимые к библиотечным и другим блокам; код эффектов не копируется.

Библиотечные стили вынесены из src/styles/blocks.scss, остальные блоки пока остаются там. npm run styles собирает styles.css и Blocks/blocks.css. Страницы подключают оба CSS, Modifications/modifications.css и оба обычных JS: сначала Modifications/modifications.js, затем Blocks/blocks.js. Vite собирает четыре страницы сайта и служебный noindex-каталог. Галерея управляется только Blocks/blocks.js; ScrollReel и просмотрщик остаются модификациями. Контент не дублируется: общая images/, элементы интерфейса — Blocks/images/. Документация обеих библиотек обновляется автоматически в рамках изменений.


Статические главная, список кейсов и отдельный кейс Brodeks на обычном HTML и SCSS, без шаблонизатора; локальный JS используется для согласованных модификаций: курсора и мобильных превью кейсов, smart-header, SmoothScroll 1.4.10 с CDN, управления автозапуском видео, вкладок/прокрутки новых блоков и просмотра картинок, параллакса и следующего кейса . Тексты и разметка находятся в `index.html`, `cases.html` и `case.html`.

## Просмотр

Откройте корневой **index.html** двойным щелчком. Либо запустите **OPEN-SITE.cmd**. Node.js, установка зависимостей и локальный сервер для просмотра не нужны. CSS и изображения уже находятся в репозитории.

## Разработка

Требуется Node.js >= 22.12.0. Установка: `npm ci`.

- `index.html` — разметка и контент главной.
- `cases.html` — статическая страница кейсов; открывается двойным щелчком.
- `case.html` — кейс Brodeks по оригиналу https://grammers.pro/brodeks: тексты, изображения, видео с автозапуском, галереи и награды. Откройте двойным щелчком. Изображения и видео локальные; галереи работают через нативную прокрутку и якоря без JS-слайдера. Семантическая статья с одним H1, метаданными и canonical. Подробности: `docs/brodeks.md`; ресурсы: `docs/brodeks-assets.json`. Страница включена в общую сборку Vite.
- Новые блоки в конце `case.html`: `#case-responsive-preview` (десктоп и закреплённый телефон), `#case-pages-preview` (список страниц и макет), `#case-service-preview` (две колонки). До 1023px окна всех трёх блоков автоматически прокручиваются по одному циклу; в первой паре и списке страниц есть вкладки. На desktop длинные экраны case-pages/case-columns статичны. Между колонками case-pair/case-pages увеличен промежуток, телефон отделён от десктопного кадра. Тестовый длинный скриншот взят из файла пользователя. Подключение и параметры: `docs/case-blocks.md`.
- Просмотр любой картинки: добавьте класс `photo-zoom` на обычную ссылку с img и href полного изображения. Есть увеличение, Esc, клавиатура и возврат фокуса; работает на всех страницах с общими модификациями. В одиночных изображениях используется data-image-zoom на single-image; в составных кадрах сохраняется photo-zoom.
- `project-card` в `blocks.scss` — общая карточка для обеих страниц, превью на div.
- Обычные превью кейсов — 16:9 на всех ширинах; вертикальный промежуток между рядами — 80px. На cases.html добавьте класс `project-card-featured` к article для отдельной строки: его превью высотой 85vh, экран внутри шириной максимум 900px и без зазора сверху и снизу; пример — первый Brodeks.
- Общий фон обеих страниц и шапки — белый, --color-background: #fff в `src/styles/tokens.scss`. --LightGray: #F5F6F8 сохранён для поверхностей блоков. При наведении, фокусе и мобильной эмуляции у контейнера картинки кейса появляется обводка 1px #e3e5e8.
- `src/styles/blocks.scss` — стили остальных секций сайта; библиотечные single-image/horizontal-gallery находятся в `Blocks/blocks.scss`. В обоих файлах блоки разделены русскими секциями-комментариями со звёздочками.
- `src/components/` — стили повторяемых элементов.
- [`Modifications/`](Modifications/README.md) — база эффектов: один `modifications.css` и один `modifications.js`, разделённые секциями. Курсор `.go` подключён на карточках кейсов.
- [Инструкция агентам по модификациям](Modifications/AGENTS.md) — подключение всех эффектов, опции, значения по умолчанию и API. Поддерживается автоматически при изменениях; аналогичные инструкции для переиспользуемых блоков также обновляются в рамках задачи без напоминания.
- `src/styles/main.scss` — подключение SCSS через `@use`.
- `styles.css` — скомпилированные стили для прямого открытия HTML; хранить в Git вместе с изменениями SCSS.
- `images/` — локальные изображения.
- `fonts/` — локальный NTSomic (400, 500, 600, 700), подключение в `src/styles/fonts.scss`.
- `npm run styles` — обновить CSS после правок SCSS; `npm run styles:watch` — следить за изменениями.
- `npm run dev` — необязательный сервер Vite; `npm run build` — сборка в `dist/`; `npm run preview` — проверка сборки.

После правок SCSS выполнить `npm run styles` или `npm run build` и сохранить обновлённый `styles.css`. `dist/` и `node_modules/` не коммитить.

## Получение обновлений на Windows

Разработка и проверки выполняются локально в папке проекта. Коммиты и отправка изменений в GitHub — только по явной команде пользователя; согласование правок само по себе не разрешает публикацию.

В GitHub Desktop нажмите Fetch origin, затем Pull origin, если кнопка появилась. Show in Explorer открывает папку проекта. Для автоматического получения исходников есть `SYNC-FROM-GITHUB.cmd`: только fast-forward из origin/main, без push/reset/stash, с пропуском локальных изменений и коммитов. Закройте его окно для остановки.

Ограничения оригинальных изображений и шрифта: `docs/static-home.md`, `docs/reference-assets.json`. Правила: `AGENTS.md`. Перенос в WordPress — позднее.

Плавный скролл подключён глобально через CDN SmoothScroll 1.4.10 с параметрами пользователя. Требует интернета; без CDN остаётся обычная прокрутка. При reduced motion на загрузке плавный скролл отключён.

Шапка использует модификацию smart-header: фиксируется сверху, скрывается при прокрутке вниз и появляется при прокрутке вверх. Пороги и подключение — в README модификаций.

Страница кейсов восстановлена по https://grammers.pro/cases. Состав, ресурсы и ограничения: `docs/cases.md`.

Внутри превью всех карточек добавлен CSS-эффект: затемнение, появление экрана из перспективы и прокрутка скриншота до конца. Радиус превью — 25px, экран обычного кейса и featured до 959px со скруглением от 5px до 25px при появлении; featured от 960px — от 25px до 0px; фоновая картинка отдельно не увеличивается. От 960px при наведении весь контейнер превью сжимается до 95% с transition: all 0.75s cubic-bezier(0.16, 0.44, 0, 0.97); экран появляется за те же 0.75s с этой кривой. Экран обычного кейса занимает всю область превью, в featured на десктопе имеет максимальную ширину 900px и занимает 100% высоты превью без вертикального зазора; старт экрана — perspective(1200px) translateY(0%) rotateX(7deg) scale(0.85). Тексты и ссылки сохранены. На всех 16 карточках обеих страниц временно подключён пользовательский скриншот Brodeks `images/projects/brodeks-screen.webp` (900×2400, WebP quality 92); позже заменим на индивидуальные скриншоты проектов. До 959px JS запускает эффект только у одной картинки: её центр должен находиться в пределах ± её высоты от центра видимой области экрана. Если подходят несколько картинок, активна ближайшая к центру; подписи не учитываются. Вне зоны эффект сбрасывается. Доступен фокус с клавиатуры; reduced motion отключает движение. Параметры и структура — секция 05 `Modifications/README.md`. Мобильным автозапуском управляет секция 05 общего JS; без JS остаются фото и обычные ссылки.

На ширине до 959px featured-превью имеет height: auto и aspect-ratio: 16 / 9, как обычные кейсы; ширина и max-width внутреннего экрана — 100%, без бокового зазора. Высота 85vh, боковой зазор и max-width 900px действуют от 960px.

Зацикленная прокрутка начинается через 200мс после наведения, фокуса или мобильного выбора, пока экран ещё появляется (750мс). Первый проход project-preview-scroll-start сохраняет прежнюю кривую cubic-bezier(0.25, 0.1, 0.55, 1), длительность 12с и задержку 200мс. На 12.2с его без скачка продолжает project-preview-scroll: 12с на проход, cubic-bezier(0.45, 0, 0.55, 1), infinite alternate-reverse, начиная с обратного прохода. У цикла fill-mode: forwards, поэтому он не перекрывает первый старт до окончания своей задержки. Появление маски не повторяется; reduced motion отключает анимацию. При выключении эффекта анимация снимается и позиция скриншота сразу сбрасывается в 0. Каждый новый запуск начинается с начала с задержкой 200мс; позиция не сохраняется.

GO-курсор отображается кругом #242424 с белой стрелкой и mix-blend-mode: normal. Инверсия exclusion и исходные цвета сохранены в комментариях секции 01 Modifications/modifications.css.

Композиции кейса в конце case.html: `#case-parallax-preview`, `#case-parallax-gallery`, `#case-next-project`. Параллакс изображения, смещённые колонки с подписями, строка следующего проекта с разворотом по скроллу и круглым медиакурсором. GSAP/ScrollTrigger локальные, подключены на всех трёх страницах; уменьшенное движение и пауза удержанием мыши учтены. Материалы — Brodeks и AG-technologies. Параметры и подключение: [docs/case-motion-blocks.md](docs/case-motion-blocks.md).

Фотографии: `photo-parallax` включает параллакс на контейнере с img/picture, `photo-zoom` — увеличение по клику на ссылке с изображением. Можно использовать отдельно или вместе в любом блоке. Старые data-атрибуты совместимы. Примеры, размеры кадра и API: [docs/photo-modifications.md](docs/photo-modifications.md).

Контент кейса имеет общий верхний предел `--case-content-width: 1500px` (tokens.scss). Более узкие размеры блоков сохранены. У серых поверхностей single-image surface/case-video/case-details ширина фона сохраняется, ограничивается внутреннее изображение или вся композиция через case-details__composition. Горизонтальные галереи занимают всю ширину экрана; их окно не ограничивать колонкой контента. case-next — исключение: вся ширина экрана без боковых полей контейнера.

## Горизонтальная галерея

Единый horizontal-gallery (Blocks/blocks.js) объединяет статичную ленту, равномерный цикл, реакцию на скролл и статичный режим со стрелками. data-gallery-mode: static/linear/scroll/controls. Во всех режимах нативные touch/тачпад и drag мышью; во время ручного жеста цикл приостановлен, затем продолжается с новой позиции. Стрелки связываются с экземпляром CSS-селекторами и могут быть в другом блоке. До 959px видны 20px следующей карточки. Параметры движения прежние; HorizontalGallery.init/destroy, ImageReel/CaseGallery — только псевдонимы. Прежние секции 11/12 содержат указатель на библиотеку Blocks. Концепция — controls, мобильные экраны — linear 60s, дипломы — static, детали — scroll 30s. Подключение и все настройки: [horizontal-gallery.md](docs/horizontal-gallery.md).

Горизонтальная галерея: видимая лента занимает всю ширину экрана, max-width:none; корень размещать вне узкой колонки/обрезающих предков. Заголовки/описания ограничиваются отдельно. data-gallery-zoom="true" включает увеличение, по умолчанию false; обычные img поддерживают клик и Tab/Enter/Space без дополнительных обёрток, ссылки photo-zoom внутри галереи подчиняются опции. В текущих галереях увеличение включено только у «Деталей проекта».

При запросе нового блока галереи уточнять недостающие опции одним коротким вопросом: материалы, режим, скорость/длительность, зазор, размеры и радиус карточек, увеличение по клику, стрелки/их расположение для controls. Уже согласованные параметры повторно не спрашивать. Сохранять эти настройки в data-* и инструкции автоматически.

Сервисные страницы case-columns используют ту же внешнюю ширину, что case-pair/case-pages: min(100% - 2 × --page-gutter, --case-content-width), максимум 1500px. До 1023px одинаковые поля 20px. Две равные колонки и их зазор 20px на desktop, одна колонка и цикл скриншотов на mobile сохранены.

## Одиночное изображение

Единый single-image заменяет одиночные case-media, case-cover и case-preview. data-image-layout: content (по колонке до 1500px, по умолчанию), inset (поля --image-gutter:40px), full (вся ширина), surface (серый фон с теми же внешними полями и картинка по центру до 1500px). data-image-zoom и data-image-parallax независимы, стандарт false; только true включает эффект. Один кадр data-image-frame внутри figure, без дополнительных JS-обёрток и пустых ссылок. Параметры ImageViewer/PhotoParallax прежние, код эффектов остаётся в секциях 08/09. Нет отдельного контроллера. Обложка после заголовка — inset 40px, обе опции true, появление при загрузке сохранено. Полные примеры, CSS-переменные, адаптивность и очистка: [single-image.md](docs/single-image.md). При новом блоке уточнять только недостающие опции; обновлять инструкции автоматически.

Инерция горизонтальной галереи: mouse drag затухает на 5% за условный кадр 60 Гц с учётом реального времени, без резкого snap. Статичные режимы замедляются до нуля без отскока; движущиеся плавно достигают штатной скорости ленты. Touch сохраняет браузерную инерцию: pointercancel не равен отпусканию, учитываются touchend и конец прокрутки. Возврат после native/обычного удержания — 1s expo.out от нуля. Автоматические длительности, реакция на скролл и шаг стрелок сохранены. data-gallery-inertia — служебное состояние, не записывать в HTML. Подробности в docs/horizontal-gallery.md; проверка: `node --test tests/horizontal-gallery-input.test.cjs`.

Второй эффект появления single-image: data-image-appear="rise" — y 300px→0, opacity 0→1, 1s power1.out, один раз, когда верх figure достигает 85% высоты экрана. Работает независимо от data-image-parallax и заменяет стандартное появление; отсутствие атрибута (auto) сохраняет прежнее поведение. Использует существующий PhotoParallax секции 09, без нового контроллера/обёрток, reduced motion и очистка сохранены. Тестовый блок #case-usability-image: surface, zoom false, parallax false, appear rise. При запросе нового одиночного изображения уточнять и вариант появления, если он не указан.

## Компонент и экземпляр блока

Обязательная методика: [Blocks/METHODOLOGY.md](Blocks/METHODOLOGY.md). Компонент — библиотечный исходник с общими именами/классами. Экземпляр — независимая копия для места на странице с уникальными именами/классами/ID/API; разметка в HTML страницы, стили в src/styles/pages/*.scss → styles.css, JS в src/scripts/pages/*.js. При просьбе использовать существующий блок спросить, брать существующий экземпляр или исходный компонент, если источник ещё не указан. Дальнейшие индивидуальные правки — в экземпляре; компонент и другие экземпляры не обновлять автоматически. Новое правило заменяет прежнее общее подключение компонентов к любому новому размещению. Первые изображения/галереи пока в явно описанном переходном состоянии; Cookie уже имеет три независимых экземпляра. Общие модификации при этом остаются подключаемыми эффектами, не копируются в каждый экземпляр.

Cookie: компонент03 в Blocks и экземпляры home/cases/brodeks с отдельными маркерами/контроллерами; кнопка в стиле шапки, появление900ms/скрытие600ms, подтверждение365дней. Подключение: [cookie-notice.md](docs/cookie-notice.md).

Глобальная шторка: одно синхронное подключение `Modifications/page-transition.js` в head до CSS на всех страницах. Внутри CSS, ранняя маска и контроллер; GSAP общий или автоматически локальный vendor. Атрибуты body, список страниц и хранилище не нужны. Открытие действует также при прямом входе/обновлении. В WordPress подключать один раз через общую шапку темы. API PageTransition.init/destroy/preview; прежние тайминги, reduced motion, аварийное снятие и стабильная ширина сохранены. [Подключение и параметры](docs/page-transition.md).

## Локальная разработка с автокомпиляцией

Двойной щелчок по `START-DEV.cmd` запускает Vite на http://127.0.0.1:4181/ (или `npm run dev`). Оставить окно работающим; остановка — Ctrl+C. Каталог: http://127.0.0.1:4181/Blocks/index.html. Зависимости должны быть установлены через npm ci, Node >=22.12.0. Повторно запускать на занятом порту не нужно.

Сохранение SCSS в src/styles, src/components или Blocks автоматически компилирует **оба** отслеживаемых CSS — styles.css и Blocks/blocks.css — и обновляет браузер. Ошибка Sass сохраняет предыдущий рабочий CSS и показывается в браузере/терминале; после исправления работа продолжается. HTML и обычные JS модификаций/блоков/экземпляров тоже обновляют страницу. В dev убирается локальный query v, чтобы кеш Vite не удерживал устаревшие файлы; исходный HTML и production сохраняют версии. Плагин tools/vite-live-styles.mjs, общий компилятор tools/styles.mjs.

Просмотр идёт из корня исходников, **без /dist/**. Старые /dist/index.html, /dist/cases.html, /dist/case.html, /dist/Blocks/index.html перенаправляются к живым исходным страницам. npm run build отдельно создаёт production dist; сервер preview предназначен для проверки готовой сборки. npm run styles обновляет оба CSS без сервера. Для обычного двойного щелчка по HTML Node по-прежнему не нужен. Сервер слушает только локальный 127.0.0.1, порт4181 строгий.
