# Grammers.pro

Контекст для нового чата: [`docs/HANDOFF.md`](docs/HANDOFF.md). Правила разработки: [`AGENTS.md`](AGENTS.md).

Статическая главная по странице `https://grammers.pro/home-page`, восстановленная из предоставленного браузерного архива. Тексты сохранены. Шаблоны Nunjucks и SCSS собираются в обычные HTML и CSS: **в итоговой странице нет JavaScript**.

## Посмотреть без localhost

**Windows 11:** откройте `OPEN-SITE.cmd` двойным щелчком. Он установит зависимости по lockfile, соберёт страницу и откроет `dist/index.html` в браузере. Требуется установленный Node.js 24 LTS с npm; если его нет, откроется официальная страница загрузки. После установки повторно откройте `OPEN-SITE.cmd`. Права администратора для запуска файла не нужны.

Корневой `index.html` — исходный шаблон Nunjucks. Его нельзя открывать напрямую как готовый сайт: браузер покажет инструкции шаблонизатора. Открывать нужно файл из `dist/`, который создаётся сборкой.

Те же действия вручную:

```sh
npm ci
npm run build
```

Откройте `dist/index.html` двойным щелчком. Пути относительные, все используемые изображения находятся в `dist/images/`; внешние сервисы для отображения страницы не нужны. HTML и CSS можно изучать непосредственно в `dist/`. Сгенерированные файлы не редактировать и не коммитить.

Для разработки: `npm run dev`. Для проверки сборки через HTTP: `npm run preview`. Требуется Node.js >= 22.12.0.

## Где править

- `src/pages/home.njk` — порядок секций главной.
- `src/layouts/base.njk` — каркас документа, метаданные и подключение CSS.
- `src/blocks/<name>/<name>.njk` и `<name>.scss` — разметка и стили конкретного блока.
- `src/components/` — кнопка, заголовок секции, вывод исходных переносов строк.
- `src/data/home.json` — тексты и контент; используется только при сборке, не попадает в браузер как JS.
- `src/styles/main.scss` — явное подключение стилей блоков через `@use`.
- `src/styles/{tokens,base,layout}.scss` — общие настройки, базовая типографика и контейнер.
- `public/images/` — локальные ресурсы страницы.
- `docs/static-home.md` — особенности восстановления, проверки и ограничения ресурсов.
- `docs/reference-assets.json` — соответствие локальных файлов адресам оригинальных изображений.
- `docs/architecture.md`, `AGENTS.md` — архитектура и правила дальнейшей разработки.

jQuery остаётся в зависимостях для последующих этапов. Текущая главная его не подключает. GSAP, плавный скролл, обработка формы и всплывающие окна сейчас не реализуются.

## Автоматическое получение файлов на Windows 11

Если репозиторий уже открыт в GitHub Desktop:

1. Один раз нажмите **Fetch origin**, затем **Pull origin**, если эта кнопка появилась, чтобы получить файл запуска.
2. Нажмите **Show in Explorer**.
3. Откройте двойным щелчком `SYNC-FROM-GITHUB.cmd`.
4. Пока окно открыто, каждые 30 секунд проверяется `origin/main` и получаются новые коммиты. Закройте окно для остановки.

Используется Git из PATH или встроенный Git установленного GitHub Desktop. Лаунчер запускает встроенный Windows PowerShell с политикой RemoteSigned только для текущего процесса; постоянные настройки Windows не меняются. Скрипт не требует прав администратора.

При локальных правках, новых неотслеживаемых файлах, другой ветке или локальных коммитах автоматическое обновление пропускается. Файлы не сбрасываются, не прячутся в stash и не отправляются в GitHub. Если нужно сохранить свои изменения в GitHub, остановите окно синхронизации, выполните Commit и Push в GitHub Desktop, затем запустите его снова. При конфликте историй разберите изменения вручную в GitHub Desktop.

Это получение **исходников**. `dist/` не хранится в Git и не пересобирается скриптом: для обновления готовой страницы выполните `npm run build`. При работе через уже запущенный `npm run dev` Vite обновляет страницу вслед за исходниками.

Технический запуск одного прохода: `powershell -NoProfile -ExecutionPolicy RemoteSigned -File tools/sync-from-github.ps1 -Once`. Интервал можно изменить параметром `-IntervalSeconds 60`.

Для проверки самого скрипта: `python -m unittest discover -s tests -v` при наличии Git и PowerShell (`pwsh` или `powershell`). Тесты используют временные локальные репозитории, без GitHub и изменения рабочего проекта.
