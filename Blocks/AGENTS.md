# Инструкция агентам: библиотека блоков

Новая brodeks.html собрана из независимых копий последних текстовых экземпляров case.html; компоненты04–06 не менялись. Состав, классы, настройки, доступность и очистка: [docs/brodeks-story.md](../docs/brodeks-story.md).

## Обязательная методика компонентов и экземпляров

Сначала прочитать [METHODOLOGY.md](METHODOLOGY.md). Компонент — исходник в библиотеке; экземпляр — его независимая копия с уникальными именами/классами, разметкой в HTML страницы, CSS/JS в коде страницы. При просьбе использовать существующий блок спросить, брать существующий экземпляр или исходный компонент, если источник ещё не назван. Индивидуальные правки выполнять в экземпляре; компонент не менять автоматически. Параметры и зависимости эффектов остаются в библиотеке модификаций.

Правила общих blocks.scss/blocks.js ниже относятся к компонентам библиотеки и её каталогу. Для новых экземпляров создавать изолированные стили/контроллеры страницы по методике. Ранее установленные single-image/horizontal-gallery пока используют общие подключения — это переходное состояние; не переносить их массово без согласованной задачи. Новые Cookie уже оформлены компонентом и тремя отдельными экземплярами.


## Иерархия и размещение

Библиотека блоков первична. Блок задаёт семантический DOM, оформление и собственное управление. Модификация добавляет независимый эффект к блоку библиотеки или другому подходящему элементу страницы. Не превращать блок в модификацию только потому, что у него есть JS, и не копировать эффекты в блок.

- Каталог: [README.md](README.md); рабочие варианты: [index.html](index.html).
- Разметка: [templates/single-image.html](templates/single-image.html), [templates/horizontal-gallery.html](templates/horizontal-gallery.html). Это фрагменты для корневых HTML, а не отдельные страницы.
- Единственный исходник библиотечных стилей: blocks.scss, результат — blocks.css. Сохранять SCSS-вложенность и секции «БЛОК NN / название»; не дублировать правила в src/styles/blocks.scss или Modifications/modifications.css.
- Собственное поведение: blocks.js, секции блоков. Одиночному изображению отдельный контроллер не нужен; оно подключает эффекты из Modifications. Галереей управляет HorizontalGallery здесь; автоматический цикл предоставляет общий ScrollReel из модификаций.
- images/ — только ресурсы интерфейса. Контент — общая images/; в WordPress — медиатека. Не копировать фотографии примеров в библиотеку.
- Остальные блоки пока остаются на своих местах. Добавлять их в библиотеку по запросу пользователя.

## Подключение

В корневом HTML, один раз на страницу, с текущей общей версией ресурсов:

```html
<link rel="stylesheet" href="./styles.css?v=20261021-brodeks-story-1">
<link rel="stylesheet" href="./Blocks/blocks.css?v=20261021-brodeks-story-1">
<link rel="stylesheet" href="./Modifications/modifications.css?v=20261021-brodeks-story-1">
<script defer src="./Modifications/vendor/gsap.min.js"></script>
<script defer src="./Modifications/vendor/ScrollTrigger.min.js"></script>
<script defer src="./Modifications/modifications.js?v=20261021-brodeks-story-1"></script>
<script defer src="./Blocks/blocks.js?v=20261021-brodeks-story-1"></script>
```

Перед этими скриптами также сохранять согласованный SmoothScroll с CDN и SRI из head действующей страницы. Здесь сокращённый пример локальных подключений, а не замена всего head. Все исходные страницы, включая каталог, уже подключены. Для вложенных страниц исправить относительные пути. Vite копирует оба обычных JS и локальные библиотеки, подключает их в том же порядке. Без модификаций статичные изображения и ручная галерея доступны; без GSAP галерея сохраняет управление, без JS — нативный скролл. Эффекты не должны скрывать контент навсегда.

## 01. Одиночное изображение — single-image

Семантика: figure.single-image[data-single-image] → div.single-image__frame[data-image-frame] → img или picture; необязательный figcaption.single-image__caption. width/height и содержательный alt обязательны; loading=lazy для нижних изображений, для важной обложки — по её положению. Лишние обёртки и пустые ссылки не нужны. Фрагменты: [шаблон](templates/single-image.html), полное руководство: [single-image.md](../docs/single-image.md).

| Настройка | По умолчанию | Варианты / назначение |
| --- | --- | --- |
| data-image-layout | content | content: колонка до 1500px; inset: поля от экрана; full: вся ширина; surface: серая поверхность с полями, внутреннее медиа до 1500px |
| data-image-zoom | false | Только true включает ImageViewer |
| data-image-parallax | false | Только true включает PhotoParallax со стандартным появлением |
| data-image-appear | auto | rise заменяет стандартное появление; auto/отсутствие/неизвестное значение сохраняет прежнее поведение |
| --image-gutter | 40px | Внешние поля inset/surface |
| --image-radius | 0px | Скругление кадра |
| --image-ratio | auto | Пропорции кадра |
| --image-height | auto через fallback | Фиксированная/адаптивная высота при необходимости |
| --image-surface-color | #e8e8e8 | Цвет поверхности |
| --image-surface-padding | 8vw | Вертикальные поля поверхности |

Эффекты независимы от ширины/фона. Параллакс: scale1.05, yPercent−10→10, scrub true. rise: y300px→0 и opacity0→1 за1s power1.out, один раз при top85% внешней figure. Это константы модификаций, отдельных публичных настроек времени/силы/старта пока нет. Без параллакса и без rise блок статичен. У surface фон не движется вместе с кадром. Сохранять параметры модификаций; справочник — [Modifications/AGENTS.md](../Modifications/AGENTS.md), секции08/09.

Контентная ширина использует --page-gutter (40px, до959px20px) и --case-content-width1500px. Поля inset/surface остаются40px, пока явно не заданы иначе. full означает ширину, а не принудительную высоту100vh. Варианты single-image-cover/preview/following сохранены для совместимости существующих страниц; их размеры описаны в профильном документе. Не активировать кейсовые варианты при вставке обычного изображения.

У zoom JS делает существующий кадр доступной кнопкой (Tab/Enter/Space), просмотрщик возвращает фокус. Без JS — обычное изображение. Reduced motion отключает движение. Отдельного SingleImage.init нет: после динамического изменения опций использовать ImageViewer.destroy()/init() и PhotoParallax.destroy()/init(); не пересоздавать их для каждого статичного экземпляра. При удалении всех эффектов очищать эти API; они восстанавливают атрибуты/стили и удаляют анимации/обработчики.

При запросе блока уточнять одним вопросом только недостающее: материал, ширина/фон, поля, зум, параллакс, появление, радиус, нужная высота. Согласованные значения повторно не спрашивать.

## 02. Горизонтальная галерея — horizontal-gallery

Корень .horizontal-gallery[data-horizontal-gallery] → окно [data-gallery-viewport] → flex-трек [data-gallery-track] → непосредственные карточки [data-gallery-item]. ul/li или div/figure равноправны. Окну tabindex=0 и доступное название; каждому экземпляру уникальный ID. Разметка и четыре режима: [шаблон](templates/horizontal-gallery.html); подробности: [horizontal-gallery.md](../docs/horizontal-gallery.md).

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| data-gallery-mode | static | static: ручная; linear: равномерно влево; scroll: с направлением скролла; controls: ручная со стрелками |
| data-gallery-zoom | false | Только true включает ImageViewer для карточек |
| data-gallery-duration | 300ms | Переход стрелок/клавиатуры; 0 мгновенно |
| data-gallery-linear-duration | 60s | Проход последовательности в linear |
| data-gallery-scroll-duration | 15s | Базовый проход в scroll |
| data-gallery-prev-selector | локальный .horizontal-gallery__prev | CSS-селектор внешних button назад |
| data-gallery-next-selector | локальный .horizontal-gallery__next | CSS-селектор внешних button вперёд |
| --gallery-gap | 0px | Промежуток карточек |
| --gallery-padding | 0px | Поля трека |
| --gallery-card-width | auto | Ширина карточки на desktop; без настройки — размер изображения |
| --gallery-radius | 0px | Скругление изображений |

Стрелки могут быть вне блока: класс/селектор уникален для экземпляра, button с aria-controls на ID окна; контейнер data-gallery-controls и кнопки hidden до JS. Один клик — одна карточка по её фактической ширине с зазором, последний шаг ограничен краем. Не задавать таблицу пиксельных шагов по брейкпоинтам. Режимы/длительности невалидного значения получают текущий fallback. Длительности циклов положительные; точные правила в профильном документе.

Лента размещается вне узких/обрезающих предков, ограничивается краями экрана. До959px карточка оставляет20px следующей в выровненной позиции; desktop сохраняет собственные размеры фото/варианта. Все режимы поддерживают мышь с инерцией, native touch/тачпад, клавиатуру; вертикальный скролл остаётся вертикальным. Инерция, пауза удержанием, реакция на скролл и кривые сохранены, новых публичных data-опций для констант нет. Не добавлять кнопки паузы.

Контроллер HorizontalGallery из blocks.js подключает ScrollReel (модификации, секция10) для linear/scroll и ImageViewer (секция08) при zoom. Без них ручная галерея работает. Параллакс можно явно применить к отдельному подходящему кадру внутри карточки, но на треке уже работает управление движением — не назначать ему конкурирующий transform. При необходимости совместного нового эффекта проверить его жизненный цикл и исходные размеры.

HorizontalGallery.init()/destroy() повторно безопасны. Destroy отменяет rAF/инерцию/таймеры/наблюдателей/события, удаляет клоны и возвращает исходные атрибуты/стили/захват указателя. После динамического изменения карточек или режима — destroy/init. ImageReel и CaseGallery — совместимые имена того же API, не отдельный код. Не сохранять в HTML служебные ready/dragging/animating/inertia/reel-атрибуты и клоны. Reduced motion отключает автоцикл и инерцию, стрелки мгновенные; без JS доступно нативное окно. Проверка: node --test tests/horizontal-gallery-input.test.cjs.

При запросе галереи уточнять только недостающее одним вопросом: материалы, режим, длительность, зазор, размеры/радиус, зум, расположение стрелок. Текущие экземпляры case.html и их утверждённые настройки сохранять.

## Добавление и изменение блока

1. Сначала найти существующий блок; выбрать его параметры, затем независимые модификации. Изучить профильный документ и код, сохранить минимальный DOM, адаптивность и текущие параметры.
2. Добавить именованную секцию в общий blocks.scss и при необходимости blocks.js; не дублировать эффект из Modifications. Разметку добавить в templates, варианты показать в каталоге index.html с уникальными связями. У блоков без собственного JS явно указать используемые модификации.
3. Интерфейсные ресурсы — images/ этой библиотеки, контент — общая папка. Не добавлять внешнюю атрибуцию эффектов, технические лицензии библиотек сохранять.
4. В той же задаче автоматически обновить этот AGENTS, README-каталог, профильные docs и справочник модификаций при изменении связи. Фиксировать значения по умолчанию, публичные опции отдельно от констант, зависимости, адаптив, доступность, fallback, очистку и совместимость. Корневые AGENTS/README/architecture синхронизировать при изменении структуры/правил.
5. npm run styles обновляет styles.css и Blocks/blocks.css; после HTML/CSS/JS выполнить npm run build, проверить нужное поведение на desktop/mobile, git diff --check. Каталог не добавлять в публичную навигацию сайта. Никаких коммитов/push без команды пользователя.

## 03. Компонент Cookie и его экземпляры

[Шаблон](templates/cookie-notice.html), блок03 в blocks.scss/js, иконка images/cookie.svg. Корень data-cookie-notice, кнопка data-cookie-notice-accept, уникальные ID и aria-labelledby. data-cookie-notice-preview включает ручной пример без сохранения; data-cookie-notice-show="ID" на кнопке показывает нужный пример. CookieNotice.init/destroy/show(id); собственный контроллер без GSAP, WAAPI. Появление900ms translateY120%→0 cubic-bezier(.33,1,.68,1), скрытие600ms обратно cubic-bezier(.32,0,.67,0); reduced motion мгновенно. Размеры fluid, кнопка в стиле шапки59px/26px/18px, слабая тень на белом фоне. Текст/политика — HTML, анимационные значения и365дней — константы, не публичные data-настройки.

Подтверждение общее365дней: cookie grammers_cookie_notice и резерв localStorage grammers:cookie-notice. Preview ничего не сохраняет. Без хранилища скрывается до перезагрузки; безJS hidden-плашка не появляется, сайт доступен. Автопоказ после входящего перехода ждёт page-transition:ready, фокус не перехватывается; после ручного примера возвращается к вызвавшей кнопке. destroy отменяет анимацию/события и восстанавливает атрибуты. Это уведомление не подключает аналитику/трекеры.

Экземпляры home/cases/brodeks имеют уникальные классы и корни data-cookie-notice-home/cases/brodeks, SCSS src/styles/pages/*.scss и JS src/scripts/pages/*.js с API HomeCookieNotice/CasesCookieNotice/BrodeksCookieNotice. Общий CookieNotice не инициализирует эти корни. Подробности, карта экземпляров и правила копирования: [cookie-notice.md](../docs/cookie-notice.md), [методика](METHODOLOGY.md).

## 04–06. Текстовые компоненты

text-summary, text-tasks, text-feature: [полное руководство](../docs/text-blocks.md), шаблоны templates/text-*.html, секции04–06 общих SCSS/JS. Общая ось до1500px, поля через --page-gutter, до1023px одна колонка; до639px уменьшенные шрифты/номера. CSS-опции --text-content-width, --text-space-before/after, --text-column-gap; значения и брейкпоинты в руководстве. Части можно удалять целиком: единственный ребёнок занимает всю сетку; убрать неверный aria-labelledby при удалении заголовка. Пустых обёрток не оставлять.

Нет своего контроллера и изображений интерфейса. data-text-reveal на корне и data-text-reveal-item на описании/абзацах/пунктах включают общий TextReveal14: opacity0→1,3s cubic-bezier(.19,1,.22,1), один раз при top bottom; заголовки статичны. Задержки списка0/.1/.2…s, явная опция data-text-reveal-delay в секундах; root=false отключает эффект. Нужны GSAP/ScrollTrigger; без них/JS и при reduced motion текст виден. Очистка TextReveal.destroy/init; не дублировать эффект в blocks.js или JS страницы. Три независимых экземпляра Brodeks стоят после #case-usability-image, уникальные классы с -brodeks, HTML case.html, CSS pages/brodeks.scss; исходники библиотеки от них не зависят. Проверка node --test tests/text-reveal.test.cjs.
