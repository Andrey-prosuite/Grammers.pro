# Методика блоков: компонент и экземпляр

Это обязательная методика для дальнейшей работы с блоками. Новое указание пользователя имеет приоритет над прежним правилом общего библиотечного CSS/JS для всех установленных блоков.

## Термины

**Компонент блока** — исходник в библиотеке Blocks. У него общее название, общие классы, шаблон разметки, стили, собственный JS и/или явно подключаемые модификации, интерфейсные ресурсы и инструкции. Компонент служит заготовкой; его примеры живут в каталоге библиотеки.

**Экземпляр блока** — копия компонента или другого экземпляра для конкретного места на странице. Его имя, классы, ID, селекторы и собственный JS API получают уникальную добавку, обозначающую страницу и назначение. Разметка находится прямо в HTML страницы, стили и собственный JS — в коде страницы. Все дальнейшие индивидуальные правки выполняются в экземпляре. Изменение экземпляра не должно менять компонент или соседние экземпляры; изменение компонента не переносится в существующие экземпляры автоматически.

**Модификация** — независимый подключаемый эффект из Modifications. Она применима к компоненту, экземпляру или другому подходящему элементу страницы. Её код не копируется целиком в JS каждого экземпляра: экземпляр явно подключает эффект через документированные метки/опции. Собственное поведение блока и подключение модификации описываются отдельно.

## Обязательный вопрос перед использованием

Когда пользователь просит использовать/поставить уже существующий блок, спросить: **«Использовать существующий экземпляр или исходный компонент блока?»** При необходимости назвать доступные экземпляры и места, где они стоят. Если источник пользователь уже указал, повторный вопрос не нужен.

Если выбран экземпляр, уточнить какой, когда выбор неоднозначен. Для нового места создать его независимую копию с новым именем; не подключать автоматически чужие классы и контроллеры. Если выбрано изменение уже установленного экземпляра, править именно его на месте. Если выбран компонент, создать новый экземпляр из библиотечного исходника. Остальные недостающие настройки блока можно уточнить в том же вопросе, не добавляя лишнего согласования.

Создание нового компонента с нуля — отдельная задача. После согласованного создания оформлять его установки как экземпляры. Предложение/согласование правок не разрешает коммит или push.

## Имена и расположение

Пример компонента: single-image, single-image__frame. Его экземпляр для Usability Brodeks: single-image-brodeks-usability, single-image-brodeks-usability__frame. Для других мест — другая добавка. Не ограничиваться одним уникальным ID при сохранении конкурирующего общего контроллера.

- Компоненты: Blocks/templates/*.html, секции Blocks/blocks.scss и Blocks/blocks.js, инструкции Blocks/AGENTS.md, интерфейсные изображения Blocks/images/.
- Разметка экземпляра: соответствующий index.html / cases.html / case.html.
- SCSS экземпляров: src/styles/pages/home.scss / cases.scss / brodeks.scss (или файл новой страницы). Подключаются через src/styles/main.scss, результат — styles.css. Внутри файла разделять экземпляры русскими секциями.
- Собственный JS экземпляров: src/scripts/pages/home.js / cases.js / brodeks.js. Подключается обычным defer после общих модификаций. Vite должен копировать его и сохранять относительный путь для file://.
- Нет собственного JS — не создавать пустой контроллер. Указать подключаемые модификации и их очистку.
- Контентные изображения: общая images/ или медиатека WordPress. Интерфейсные неизменяемые ресурсы можно подключать явно из Blocks/images/; при индивидуальном изменении сделать ресурс экземпляра, не менять общий оригинал.

## Как создать экземпляр

1. Выяснить источник: компонент или выбранный существующий экземпляр. Прочитать его инструкцию, опции, зависимости и ограничения.
2. Скопировать только необходимую разметку, сохранить семантику и компактный DOM. Вставить в HTML целевой страницы. Добавить уникальное имя, заменить все связанные классы, ID, aria-controls/labelledby и внешние селекторы стрелок.
3. Перенести CSS исходника в SCSS страницы и заменить селекторы на селекторы экземпляра. Сохранять вложенность, параметры/адаптив и согласованные анимации. Не оставлять неявную зависимость от общих классов компонента.
4. При собственном JS скопировать контроллер в JS страницы, заменить имя API и корневые селекторы. Один DOM-экземпляр не должен одновременно инициализироваться общим компонентом и своей копией. Не копировать глобальные псевдонимы API, относящиеся ко всем блокам библиотеки.
5. Подключить нужные модификации явно. Общие data-опции эффекта можно сохранить, если они относятся к публичному API эффекта; уникальные метки инициализации собственного контроллера должны исключать двойной запуск.
6. Дальнейшие индивидуальные изменения делать в экземпляре. Не переписывать компонент ради одной страницы. Если пользователь просит изменить сам исходный компонент, обновить библиотечную разметку, CSS/JS, пример и справочник; существующие экземпляры обновлять только в согласованном объёме.
7. Автоматически обновить карту экземпляров и инструкции: происхождение внутри проекта (компонент/экземпляр), имена, HTML/CSS/JS, настройки, эффекты, зависимости, адаптивность, доступность, очистку и совместимость. Внешнюю атрибуцию эффектов не добавлять.
8. Собрать CSS/production, проверить нужное поведение, mobile/desktop, отсутствие двойного запуска и git diff --check. Git — только по команде пользователя.

## Текущее состояние

Первые single-image и horizontal-gallery были установлены до этой методики и пока используют общие подключения библиотеки. Это явно отмеченное переходное состояние, а не образец создания новых экземпляров. Новая методика не означает молчаливого массового переименования уже работающих блоков. При дальнейшей установке/переработке уточнять источник и объём переноса.

Cookie оформлена по новой методике:

| Компонент / экземпляр | Разметка | CSS | JS / API |
| --- | --- | --- | --- |
| cookie-notice | Blocks/templates/cookie-notice.html; пример Blocks/index.html | Blocks/blocks.scss, блок03 | Blocks/blocks.js, CookieNotice |
| cookie-notice-home | index.html | src/styles/pages/home.scss | src/scripts/pages/home.js, HomeCookieNotice |
| cookie-notice-cases | cases.html | src/styles/pages/cases.scss | src/scripts/pages/cases.js, CasesCookieNotice |
| cookie-notice-brodeks | case.html | src/styles/pages/brodeks.scss | src/scripts/pages/brodeks.js, BrodeksCookieNotice |

У экземпляров отдельные корневые data-cookie-notice-home/cases/brodeks, поэтому библиотечный CookieNotice их не запускает. Подтверждение общее для сайта (один cookie/резерв localStorage), контроллеры и классы независимы. Это намеренная общая настройка состояния, а не общий экземпляр.

## Индивидуальный хиро главной

hero-home — переработанный на месте экземпляр главной, без нового библиотечного компонента. HTML в index.html, SCSS в src/styles/pages/home.scss, собственного JS нет. При последующем использовании уточнять источник по общей методике. Карта ресурсов, настройки и адаптив: [home-hero.md](../docs/home-hero.md).

## Галерея логотипов главной

clients-home — независимый экземпляр исходного компонента horizontal-gallery, источник явно выбран пользователем. HTML index.html, SCSS src/styles/pages/home.scss, JS src/scripts/pages/home.js, API HomeClientsGallery. Корень data-clients-home-gallery исключает запуск общего HorizontalGallery; ScrollReel остаётся общей модификацией. [Инструкция](../docs/home-clients-gallery.md).

## Галерея наград главной

awards-home создана из существующего экземпляра clients-home по указанию пользователя; независимые классы/data-awards-home-gallery и API HomeAwardsGallery. HTML index.html, SCSS/JS страницы home, общий ScrollReel. [Инструкция](../docs/home-awards-gallery.md).

## Текстовые компоненты и экземпляры Brodeks

Новая brodeks.html использует независимые копии последних экземпляров case.html: text-summary-brodeks-story, text-tasks-brodeks-story-tasks/results и text-feature-brodeks-story-{место}. Стили pages/brodeks-story.scss; cookie-notice-brodeks-story с отдельным BrodeksStoryCookieNotice в pages/brodeks-story.js. [Карта, настройки и пустые кадры](../docs/brodeks-story.md).

Компоненты04–06 text-summary/text-tasks/text-feature установлены как независимые экземпляры text-summary-brodeks/text-tasks-brodeks/text-feature-brodeks в case.html после изображения «Юзабилити сайта». Стили скопированы в src/styles/pages/brodeks.scss с уникальными селекторами; общего класса компонента у экземпляров нет. Собственный JS не требуется, общий TextReveal подключён data-метками. Не копировать этот эффект в страницу. [Состав, частичные варианты и карта экземпляров](../docs/text-blocks.md).
